## Интеграция box- и гладкого plateau-polynomial ядра

В исходной реализации после вычисления анизотропного расстояния

[
q_{ij}=|T_k(X_i-x_j)|^2
]

для каждой пары ((i,j)) вычисляется вещественный вес

[
w_{ij}=K(q_{ij}).
]

При использовании компактного ядра все пары с

[
q_{ij}\ge1
]

имеют нулевой вес и не участвуют в построении локальных статистик. Поэтому вычисление ядра следует отделить от построения support: сначала exact projected screening формирует множество

[
\mathcal N_j={i:q_{ij}<1},
]

и только для элементов этого множества определяется конкретное значение веса. Это позволяет использовать один и тот же механизм поиска соседей для разных типов ядра.

Вместо одного фиксированного kernel необходимо реализовать два взаимозаменяемых режима:

[
K_{\mathrm{box}}(q)=
\begin{cases}
1,&q<1,\
0,&q\ge1,
\end{cases}
]

и гладкое plateau-polynomial ядро

[
K_{\tau}(q)=
\begin{cases}
1,&0\le q\le\tau,[1mm]
1-10s^3+15s^4-6s^5,&\tau<q<1,[1mm]
0,&q\ge1,
\end{cases}
\qquad
s=\frac{q-\tau}{1-\tau},
]

где (0<\tau<1).

Оба ядра имеют одну и ту же внешнюю границу support,

[
q<1,
]

поэтому projected screening, spatial index, candidate lists и точное вычисление анизотропных расстояний должны быть общими для обоих режимов. После построения support меняется только этап формирования весов.

### Box-режим

При box-ядре каждый элемент support имеет вес

[
w_{ij}=1.
]

Поэтому значения весов хранить не требуется. Для каждого центра достаточно сохранить только массив индексов

[
\mathcal N_j.
]

Локальная масса непосредственно равна

[
m_j=|\mathcal N_j|.
]

Если используются нормированные веса, то для всех соседей

[
a_{ij}=\frac1{|\mathcal N_j|}.
]

Таким образом, статистический этап получает только neighbor list и может использовать одинаковый коэффициент для всех локальных наблюдений.

Это даёт три практических преимущества.

Во-первых, память на хранение float weights полностью устраняется. В sparse representation одно ребро содержит только индекс наблюдения.

Во-вторых, если между двумя outer-итерациями support центра не изменился,

[
\mathcal N_j^{(k)}
==================

\mathcal N_j^{(k-1)},
]

то вся строка весов также не изменилась. Следовательно, можно точно переиспользовать локальное среднее, локальную centered geometry и другие объекты, зависящие только от весов и support.

В-третьих, центры с одинаковыми support можно обнаруживать хешированием отсортированных neighbor lists. При одинаковой схеме направлений такие центры имеют одинаковую локальную weighted geometry и могут быть обработаны совместно или схлопнуты в одного представителя с multiplicity. Для box такое схлопывание значительно естественнее, поскольку одинаковый support автоматически означает одинаковые normalized weights.

Поэтому box-режим следует использовать как максимально быстрый backend, особенно на промежуточных outer-итерациях, когда основная задача состоит в быстром уточнении (P_k), а структура neighborhoods ещё заметно меняется.

### Plateau-polynomial режим

Полностью бинарные веса box-ядра не различают центральные и пограничные наблюдения. Чтобы сохранить преимущества равных весов внутри устойчивой части neighborhood, но уменьшить влияние точек около границы support, вводится plateau-polynomial ядро.

Его support остаётся тем же:

[
q<1.
]

Однако внутри support появляются две области:

[
\mathcal I_j
============

{i:q_{ij}\le\tau},
]

и

[
\mathcal B_j
============

{i:\tau<q_{ij}<1}.
]

Для внутренней области

[
w_{ij}=1,
]

поэтому её можно обрабатывать так же, как box-ядро.

Только для boundary-set

[
\mathcal B_j
]

необходимо вычислять и хранить вещественные веса.

Таким образом, вместо хранения float weight для каждого ненулевого ребра необходимо хранить:

[
\text{neighbor index}
]

для всех элементов support и

[
\text{float weight}
]

только для boundary edges.

Если

[
E=\sum_j|\mathcal N_j|
]

— общее число ненулевых рёбер, а

[
B=\sum_j|\mathcal B_j|,
]

то количество явно хранимых вещественных весов уменьшается с

[
O(E)
]

до

[
O(B),
\qquad B\le E.
]

После восстановления весов вычисляется

[
m_j=\sum_{i\in\mathcal N_j}w_{ij},
\qquad
a_{ij}=\frac{w_{ij}}{m_j},
]

и далее используются те же функции построения статистик, что и для обычного compact kernel.

### Общая структура реализации

В коде ядро не должно отвечать за поиск соседей. Необходимо разделить алгоритм на два независимых слоя.

Первый слой, `NeighborhoodEngine`, отвечает только за геометрию:

[
(P_k,\Lambda_k,\alpha_k,h_k)
\longrightarrow
q_{ij}
\longrightarrow
\mathcal N_j.
]

Он выполняет projected screening, radius search и точную проверку (q_{ij}<1).

Второй слой, `KernelBackend`, получает уже готовые значения (q_{ij}) только для support и преобразует их в веса.

Для box:

[
q_{\mathcal N_j}
\longrightarrow
\text{implicit }w=1.
]

Для plateau-polynomial:

[
q_{\mathcal N_j}
\longrightarrow
{\mathcal I_j,\mathcal B_j,w_{\mathcal B_j}}.
]

После этого оба backend передают данные в один общий `StatisticsBuilder`.

Такое разделение важно, потому что дорогостоящая часть — получение кандидатов и вычисление анизотропных расстояний — не должна дублироваться для разных ядер.

### Переиспользование между outer-итерациями

Для обоих ядер следует хранить предыдущий support и предыдущие значения (q_{ij}) для активных или пограничных пар.

Для box достаточно определить, пересекла ли пара границу

[
q=1.
]

Если она гарантированно осталась внутри,

[
q<1,
]

то её вес всё ещё равен (1).

Если она гарантированно осталась снаружи,

[
q\ge1,
]

то её вес всё ещё равен (0).

Следовательно, пересчитывать необходимо прежде всего пары, способные пересечь границу support.

Для plateau-polynomial существуют две существенные границы:

[
q=\tau
]

и

[
q=1.
]

Если наблюдение гарантированно осталось в области

[
q\le\tau,
]

его вес точно остаётся равным (1), поэтому ни само значение веса, ни связанная с ним информация обновляться не должны.

Если оно осталось при

[
q\ge1,
]

оно по-прежнему отсутствует в support.

Полный пересчёт значения веса требуется прежде всего для элементов taper-region

[
\tau<q<1
]

и для пар, способных пересечь одну из двух границ.

Таким образом, box превращает изменение весов в задачу отслеживания одной границы, а plateau-polynomial — в задачу отслеживания небольшой boundary layer.

### Совместное использование преимуществ двух ядер

Наиболее практичная интеграция состоит не в одновременном суммировании двух kernel, а в использовании одного общего support engine и возможности переключать профиль весов.

На ранних и промежуточных outer-итерациях рекомендуется использовать box:

[
K=K_{\mathrm{box}}.
]

В этот момент (P_k) ещё заметно меняется, поэтому дорого поддерживать точные плавные веса, которые на следующем шаге всё равно могут измениться. Box позволяет максимально дешёво перестраивать neighborhoods, быстро вычислять статистики и точно переиспользовать центры с неизменившимся support.

После стабилизации (P_k) можно переключиться на plateau-polynomial:

[
K=K_\tau.
]

При этом не требуется заново разрабатывать или менять механизм projected screening: внешняя граница support остаётся

[
q=1.
]

Уже найденные neighborhoods могут быть использованы как кандидаты, после чего внутри них вычисляется лишь положение относительно (\tau) и значения taper weights.

Такой двухфазный режим использует главное преимущество box — минимальную стоимость и максимальный reuse — на этапе грубого структурного поиска, а преимущество гладкого ядра — постепенное уменьшение влияния пограничных наблюдений — на этапе финального уточнения.

Практически outer-loop принимает вид

[
\text{projected screening}
\rightarrow
\text{sparse support}
\rightarrow
\begin{cases}
\text{box weights}, & \text{structure search},\
\text{plateau-polynomial weights}, & \text{refinement},
\end{cases}
\rightarrow
\text{local statistics}.
]

Критерий переключения лучше связать не с фиксированным номером итерации, а со стабилизацией найденного EDR-подпространства, например с малым изменением проектора

[
|P_k^\top P_k-P_{k-1}^\top P_{k-1}|.
]

До достижения этого условия используется box; после достижения — plateau-polynomial.

Следует учитывать, что изменение kernel между outer-итерациями изменяет finite-sample estimator. Поэтому двухфазный режим является вычислительной модификацией алгоритма, а не точным ускорением исходного ADP. Если требуется полностью контролируемый эксперимент, оба варианта необходимо также поддерживать как независимые режимы: `box-only` и `plateau-only`.

Итоговая архитектура должна поддерживать три конфигурации:

1. `box-only` — максимальная скорость, минимальная память и наиболее сильный reuse;
2. `plateau-only` — гладкое downweighting пограничных наблюдений при сохранении компактного support;
3. `box -> plateau` — быстрый поиск структуры с последующим гладким refinement.

При этом exact projected screening, support-aware center selection и sparse statistics остаются полностью общими для всех трёх режимов.
