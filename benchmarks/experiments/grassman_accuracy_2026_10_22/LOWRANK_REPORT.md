# Low-rank correction pilot

The original target—improve full-ADP recovery error at modest runtime cost—remains unachieved. Projected10 was faster in development, but EDR was neutral versus baseline20 and there was no recovery gain over the `budget10` ablation. The exploratory `lora_k10` 1% pooled pilot gain is not independently confirmed: LoRA was absent from the frozen development arms, and the projected10 result cannot establish LoRA behavior. No candidate is promoted.

## Frozen development gate

The pre-registered development comparison used seeds 111800–111809, the same seven cases, baseline20, `budget10` (same frozen reference solver with only `max_steps=10`), `projected10`, and actual R `MEANMAVE`. All 280 fits completed with `ok`; the 70 case/seed blocks have matching x/y/truth hashes and method seeds, the snapshot hashes verify, and frozen baseline equals the reference. The fixed bootstrap uses 10,000 seed-block draws (RNG 20261022, two-sided 2.5/97.5 percentiles), retaining all seven cases per sampled seed. No validation seeds were run.

The three runs used the frozen CLI configuration below; method order was randomized within each paired case/seed by the harness. They cover 385 fits total: 105 pilot fits across seven unique seed/case blocks, plus 280 development fits across 70 new blocks, for 77 unique blocks overall. The exploratory full-rank low-rank arm uses `k=min(m,d-m)`; `candidates.solver_for("lora_k10")` provides an opt-in CPU experimental solver and was not in development.

The public callback adapter is `from ADP import ADP_solver; ADP_solver(solve_callback)`. The experiments here use the frozen `candidates.solver_for(name)` routes directly.

```sh
rtk env OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python -m experiments.grassman_accuracy_2026_10_22.benchmark --output benchmarks/results/outputs/r_sdr/grassman-lowrank22-pilot --seed 90800 --runs 1 --cases d-5,d-20,d-50,corr-0.9,rank-3,rank-4,rank-5 --methods baseline,svd_greedy10,svd1_10,svd_k10,svd_k20,lora1_10,lora_k10,lora_k20,enriched10,enriched20,MEANMAVE
rtk env OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python -m experiments.grassman_accuracy_2026_10_22.benchmark --output benchmarks/results/outputs/r_sdr/grassman-lowrank22-projected-pilot --seed 90800 --runs 1 --cases d-5,d-20,d-50,corr-0.9,rank-3,rank-4,rank-5 --methods baseline,projected10,projected20,MEANMAVE
rtk env OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 .venv/bin/python -m experiments.grassman_accuracy_2026_10_22.benchmark --output benchmarks/results/outputs/r_sdr/grassman-lowrank22-development --seed 111800 --runs 10 --cases d-5,d-20,d-50,corr-0.9,rank-3,rank-4,rank-5 --methods baseline,budget10,projected10,MEANMAVE
```

For reruns, choose a new empty `--output` directory; the harness refuses to overwrite a non-empty output.

The run snapshots preserve their exact executed source hashes. After the development snapshot, `lowrank.py` gained two guard checks (reject non-finite/negative damping and reject a non-finite proposed update); those branches are used only by low-rank candidates, not by baseline20, budget10, or projected10. `candidates.py`, `benchmark.py`, `reference.py`, and live production `grassman.py` match the frozen development snapshot, with production/reference bytewise equal. Post-run edits otherwise changed only the analyzer, tests, and report. The independent lead verification reported 214 focused tests passed, with Ruff and Pyright clean.
