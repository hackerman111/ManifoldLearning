# Сравнение ADP с R-методами восстановления EDR

Из корня репозитория:

```bash
# Посмотреть весь набор и лимиты, ничего не обучая
uv run --no-sync python -m experiments.r_sdr --profile full --dry-run

# Проверить интеграцию: 2 задачи, 10 независимых повторов, 6 методов
uv run --no-sync python -m experiments.r_sdr --profile smoke --runs 10 \
  --output benchmarks/results/outputs/r_sdr/smoke --plots

# Полное сравнение: 50 сценариев, 3000 отдельных обучений
uv run --no-sync python -m experiments.r_sdr --profile full --runs 10 \
  --output benchmarks/results/outputs/r_sdr/full --plots

# Дополнительные большие задачи и границы n <= d: 360 обучений
uv run --no-sync python -m experiments.r_sdr --profile stress --runs 10 \
  --timeout 600 --memory-mib 8192 --output benchmarks/results/outputs/r_sdr/stress --plots

# Сравнить ранги m=3,4,5 для ADP, обычного MAVE и пакетного MEANMAVE: 90 fits
uv run --no-sync python -m experiments.r_sdr --profile multi-rank --runs 10 \
  --methods ADP,MAVE,MAVE-package \
  --output benchmarks/results/outputs/r_sdr/multi-rank-three-methods-2026-10-17 --plots

# Сравнить Grassmann с обычным MAVE и пакетным MEANMAVE: 90 fits
uv run --no-sync python -m experiments.r_sdr --profile multi-rank --runs 10 \
  --methods ADP-Grassmann,MAVE,MAVE-package --grassman-steps 5 \
  --output benchmarks/results/outputs/r_sdr/multi-rank-grassman-2026-10-17 --plots
```

Требуются Python-зависимости проекта, R и R-пакет `MAVE`.
На проверенном ПК: R 4.6.1, MAVE 1.3.12. Новых зависимостей ядра нет.

## Семь частот осцилляции

`oscillation-seven` меняет только частоты в одной форме:
f_a(z)=sin(a z1) cos(1.25 a z2)+sin(1.5 a z3),
a∈{.5,1,2,3,4,6,8}. n=2000,d=20,m=3, Gaussian X, нормировка сигнала и шум .3
сохранены. a8 совпадает с прежним сценарием частот8/10/12.

Поле Case.data_key явно объединяет потоки данных разных частот:
`family-oscillatory`. Для одного сида совпадают X, B и реализация шума на всех
частотах; меняется только сигнал. При data_key=None остаётся прежний seed по
Case.name. Поле frequency действует только в новом oscillatory-frequency3.

```bash
rtk proxy python -m experiments.r_sdr --profile oscillation-seven \
  --runs 15 --seed 0 --methods ADP-Grassmann-combined,MAVE-package \
  --threads 1 --timeout 300 --memory-mib 4096 --keep-inputs --plots \
  --output benchmarks/results/outputs/r_sdr/oscillation-frequency-20261112
```

210 fits, без настройки методов по результатам. Помимо общих EDR/углов/time/RSS
и сертификатов анализируются проекции каждого истинного направления на оценённое
подпространство, парные изменения по частоте и диагностическая когерентность
сигнала в фиксированных20 соседях в истинной проекции. Последняя использует
oracle-координаты и не является весами или bandwidth ADP/MEANMAVE.

`oscillation.py` содержит точные Gaussian-моменты градиентов. Для
A(t)=(1+exp(-2t²))/2, S(t)=(1-exp(-2t²))/2, (a,b,c)=(a,1.25a,1.5a):
Var(f)=S(a)A(b)+S(c). У ненормированного G=E[∇f ∇fᵀ] диагональ равна
(a²A(a)A(b), b²S(a)S(b), c²A(c)); G13=ac exp(-(a²+b²+c²)/2), прочие
внедиагональные элементы нулевые. E∇f=(a exp(-(a²+b²)/2),0,c exp(-c²/2)).
Вспомогательная функция возвращает моменты после **популяционной** нормировки
дисперсии, отдельно от выборочной нормировки генератора. Моменты проверены
Gaussian-квадратурой, градиенты — конечными разностями. Все семь функций имеют
истинную размерность3. Средний градиент и его обнуление не определяют полноту
ADP; диагностические совпадения не доказывают причину ошибки конкретного solver.

Серия завершена: [подробный отчёт](../../results/outputs/r_sdr/oscillation-frequency-20261112/REPORT.md),
[восстановление по частотам](../../results/outputs/r_sdr/oscillation-frequency-20261112/frequency-results.png),
[градиенты и локальная когерентность](../../results/outputs/r_sdr/oscillation-frequency-20261112/diagnostics.png).
210/210 fits без ошибок, 105/105 пар проверены. MEANMAVE восстанавливает m3
15/15 только при a1; ADP — 0/15 при всех выбранных частотах. При a2 обычно
сохраняется z3, полная смешанная плоскость не найдена. Исключения и частичное
восстановление по сидам разобраны в отчёте. При a>=3 средняя EDR около случайного ориентира .9214.
У oracle20-neighbors когерентность при a2 ещё .9104, так что механизм срыва
по одной плотности наблюдений не установлен. ADP inner525/525 останавливаются
по max_steps без сертификата. Никаких настроек по этой серии не меняли.

## Семь семейств, по 15 сидов

Профиль `seven-families` фиксирует n=2000, d=20, m=3, X~N(0,I), шум .3.
Для z=XB используются ровно семь функций:

| Сценарий | f(z) |
|---|---|
| family-additive | sin(z1) + .5 z2² + .35 tanh(z3) |
| family-quadratic | z1² + .8 z2² + .6 z3² + .5 z1 z2 + .4 z2 z3 |
| family-multiplicative | z1 z2 z3 |
| family-oscillatory | sin(8 z1) cos(10 z2) + sin(12 z3) |
| family-saturating | tanh(2 z1) + tanh(2 z2) tanh(2 z3) |
| family-localized | exp(-(z1² + 2 z2² + 3 z3²)/2) |
| family-nonsmooth | max(z1,z2,z3) |

Сигнал центрируется и делится на выборочное std с ddof=0 до добавления шума.
Все функции имеют трёхмерное центральное подпространство: градиенты (почти
всюду для max) порождают R³. В тестах есть дополнительная численная проверка
ранга градиентов; она не заменяет обоснование идентифицируемости.

```bash
rtk proxy python -m experiments.r_sdr --profile seven-families \
  --runs 15 --seed 0 --methods ADP-Grassmann-combined,MAVE-package \
  --threads 1 --timeout 300 --memory-mib 4096 --keep-inputs --plots \
  --output benchmarks/results/outputs/r_sdr/seven-families-20261112
```

Это 105 наборов и 210 fits. Оба метода в каждой паре получают одинаковые
X/y/B с SHA256. Имя `ADP-Grassmann-combined` выбирает текущий публичный
combined20, а `MAVE-package` — пакетный MEANMAVE; старое имя `ADP-Grassmann`
оставлено для исторического контроля с пятью шагами. После прерывания к той
же команде добавляется `--resume`; настройки и исходники менять нельзя.
В каждой семье отдельно сравниваются EDR, max angle, recovery при EDR<=.1,
fit/process time, RSS, парные разности и неудачи. Высокочастотный и негладкий
сценарии являются стресс-тестами; результаты не предполагают успеха методов.

Серия 2026-11-12 завершена: 210/210 успешных fits, 105/105 пар проверены
независимым аудитом. [Результаты по семействам и ограничения](../../results/outputs/r_sdr/seven-families-20261112/REPORT.md).
MEANMAVE имеет меньшую среднюю EDR в шести семействах; в осциллирующем режиме
оба метода не восстановили подпространство ни на одном сиде при пороге .1.
ADP быстрее по median fit примерно в 5.1–5.3 раза, но все его inner solves
остались без сертификата. Это результат данного фиксированного протокола.

Для `--plots` нужен matplotlib из существующей группы `bench`:
`uv sync --group bench`. Без флага графиков matplotlib не импортируется.
При ограничениях на домашний каталог можно задать `MPLCONFIGDIR=/tmp/r-sdr-mpl`.

Скрипт исполняет R через установленный `Rscript`. Он сначала читает `.libPaths()`
с отключённым `.Rprofile`, затем явно передаёт пути ванильным R-процессам.
Это сохраняет доступ к пакетам, установленным в пользовательскую библиотеку
через `.Renviron`. Путь к R можно задать `--rscript /path/to/Rscript`.

```bash

  --cases d-5,d-20,d-50 --runs 10 --seed 106800 --threads 1 --keep-inputs \

```

Исходный Grassmann получает5 шагов, relative —10 с smooth cap5. `lambda_prox`
передаётся внешней ADP-моделью из `lambda_penalty` (default.05); не дублировать
его в ADP_solver. Исходные frozen manifests хранят экспериментальный прототип;
публичный port совпал с ним и oldbaseline на120 полных fit до проверки времени.

`rMAVE` здесь означает **refined**, а не robust. Обычный `MAVE` и `rMAVE`
разделены по месту вычисления весов. `MAVE-package` сохранён дополнительно,
поскольку пакетный код использует собственный внутренний алгоритм; его время
нельзя подменять временем R-реализации обычного MAVE. Пакет содержит C++-ядро.

Установленный пакет не предоставляет селекторы `dMAVE`, `rMAVE` или классический
`SIR`; `KSIR` — другой, kernel-вариант SIR. `CSMAVE` не переименовывается в dMAVE.
Методы и API проверены по [руководству MAVE](https://stat.ethz.ch/CRAN/web/packages/MAVE/MAVE.pdf).
Прежние `benchmarks/adp_mave_*` и их результаты не изменяются и не объединяются
с новым протоколом: их dMAVE-обёртка усредняла отдельно оценённые проекторы.

R-реализации в `methods.R` — проверяемые **варианты для бенчмарка**, с явно
выбранными инициализацией, bandwidth и остановкой. Это не копия авторского кода
и не утверждение о точном воспроизведении всех настроек статей.

## Сетка

Каждый выбранный сценарий выполняется для каждого метода минимум на десяти
независимых наборах данных. `--runs 9` и меньшие значения отклоняются, включая
профиль smoke. Неудачи и таймауты считаются попытками, остаются в результатах;
скрипт не гарантирует десять успешных оценок для неработоспособного режима.

| Профиль | Сценарии | Размеры | При 10 повторах и всех методах |
|---|---:|---|---:|
| `smoke` | 2 | n=60/80, d=4/5, m=1/2 | 120 fits |
| `standard` | 22 | n=100..2000, d=5..100, m=1..3 | 1320 fits |
| `full`, по умолчанию | 50 | n=100..10000, d=5..1000, m=1..3 | 3000 fits |
| `stress` | 6 | n=500..20000, d=100..2000, в том числе n<=d | 360 fits |
| `multi-rank` | 3 | n=500, d=20, additive, m=3/4/5 | 90 fits с `ADP,MAVE,MAVE-package` |

Для отдельного прогона Grassmann задаётся явно как `ADP-Grassmann`; метод не
добавлен в набор по умолчанию и не заменяет `ADP`/HPAO-LSMR. Сравнение с
обычным MAVE и `MAVE::MEANMAVE` использует те же данные и парный отчёт с
Grassmann в качестве базы. Grassmann запускается с `local_ridge=0`, `tol=1e-6`
и `max_steps=5` на каждом внешнем масштабе (`--grassman-steps`). Это его
исторический warm-start control budget; текущий public default20 представлен
методом `ADP-Grassmann-combined`. Число шагов не эквивалентно лимиту LSMR.
Inner stationarity сохраняется отдельно, а остановка внешнего ADP schedule
не объявляется сертификатом сходимости.

Полная сетка включает независимое изменение n и d; малое n/d; взаимодействия
d, m и корреляции; линейный отклик, sin, квадрат, произведение двух индексов,
аддитивную многомерную модель; AR(1)-корреляции 0/0.5/0.9/0.99; шум 0.1/0.3/1;
Gaussian, независимые t5, uniform и двухкомпонентные смеси признаков.
Состав и точные параметры показывает `--dry-run`; исходник сетки — `design.py`.

Истинный базис — случайный ортонормированный плотный B. Отклики зависят только
от z=X B: linear/sin/square используют m=1, product — m=2;
additive = sin(z1)+0.5*z2^2+0.35*sum(tanh(zj), j>=3), с пропуском отсутствующих
координат. Сигнал центрируется и делится на своё выборочное стандартное
отклонение, затем добавляется независимый Gaussian-шум указанного масштаба.
Это сравнение при **известной истинной размерности m**; подбор размерности и
настройка гиперпараметров по результатам восстановления сюда не входят.
Условное среднее и центральное подпространство этих моделей имеют одну цель.
Тяжёлые хвосты/неэллиптический дизайн и симметричные links проверяют слабые зоны
методов; низкое качество SIR на симметрии не означает ошибку реализации.

Потоки B, X и шума независимы. Внутри пары `(сценарий, seed)` все методы получают
одни и те же float64 CSV с 17 значащими цифрами. В `runs.jsonl` есть общие SHA256
массивов X,y,B и файлов CSV. Порядок методов воспроизводимо перемешан.
Разные сценарии используют разные наборы; парность между разными n/d не заявляется.

## Точный смысл R-вариантов

Общая MAVE-задача на шаге минимизирует по локальным a_j,c_j и общему B сумму

```
sum_j sum_i w_ji * (F_i - a_j - c_j^T B^T (X_i-X_j))^2.
```

Обычный MAVE фиксирует `w_ji` пропорционально
`exp(-||X_i-X_j||^2/(2h^2))`, rMAVE пересчитывает их по `B^T(X_i-X_j)`.
Веса нормированы по i для каждого j. Оба начинают с `MEANOPG` пакета.
X и y стандартизуются внутри fit; полученный базис возвращается в исходные
координаты делением строк на масштабы X и ортонормированием.
Начальный `h=2.34*n^(-1/(max(d,3)+6))`. Для refined-вариантов
`h_min=2.34*n^(-1/(m+4))`, `h_next=max(h*n^(-1/(2*(max(d,3)+6))),h_min)`.
Обычный MAVE сохраняет исходный h.
Разделение исходных и refined-весов основано на [Xia et al. 2002](https://doi.org/10.1111/1467-9868.03411).

Для dMAVE `F_ik=phi((y_i-y_k)/b)/b`, где **k пробегает все наблюдения**,
`b=1.06*n^(-1/5)` для стандартизованного y. На каждом шаге минимизируется одна
совместная сумма по j,i,k с единым B и локальными a_jk,c_jk. Инициализация —
пакетный `CSOPG`. Принцип density-response взят из [Xia 2007, раздел 2.2](https://arxiv.org/abs/math/0701761).
Здесь выбраны **фиксированный response bandwidth и отсутствие trimming**
(`rho_jk=1`), а не полная bandwidth/trimming-схема статьи. Все эти различия
считаются отдельным ESTIMATOR-вариантом и записаны в manifest/metadata.
Нет квантильного усечения числа response targets или ансамбля проекторов.

Глобальные и локальные задачи решаются QR, без ridge и нормальных уравнений.
После глобального шага B ортонормируется. Чтобы не хранить n*n откликов плотности,
F вычисляется блоками по 16 response targets. Для локального C формы m*K:
`C=U D V^T`; часть `F(I-VV^T)` не зависит от B. Поэтому глобальный LS использует
`F V` и `C V` с тем же решением. Это точное сокращение, без отбрасывания сингулярных
компонент. R-фактор QR накапливается по центрам; весь n*n*d дизайн не строится.
Память этого reference-шага порядка `O(n*d*m+(d*m)^2+n*m)`, плюс блок откликов;
пакетная OPG-инициализация имеет собственные затраты. Вычислительная цена полного
dMAVE всё равно велика: проход по всем j и k даёт кубический по n компонент.
Большие случаи могут честно завершаться по лимиту.

SIR следует [Li 1991](https://doi.org/10.1080/01621459.1991.10475035): SVD центрированного X
даёт whitening, затем SVD взвешенных средних срезов и обратное преобразование
направлений. Квантильные срезы type=1 сохраняют одинаковые y вместе; по умолчанию
их запрошено 10, фактическое число записано в detail. При вырожденной ковариации,
n<=d или недостатке срезов метод возвращает ошибку; скрытого PCA/ridge-аналога нет.

Максимум R-итераций — 25 (`--r-iterations`), порог изменения подпространства —
1e-5 (`--r-tolerance`). Для rMAVE/dMAVE он проверяется после достижения h_min.
Это критерий остановки последовательности, не доказательство глобального минимума.
`max_iterations` и траектория h/изменений базиса сохраняются.

ADP по умолчанию получает `N_J=min(n,300)`, `N_lin=min(n,max(d+2,2d))`,
`N_phi=max(m+1,min(d,12))`, `N_loc=20`, local initialization, select_step=best.
Остальные настройки берутся из текущего `ADP_Config`; исходник сохранён в snapshot.
Внутренний LSMR: до 80 HPAO-шагов, tol=1e-6 (`--solver-steps`). Для Grassmann
отдельно задаются до 5 core-GN-шагов на масштаб (`--grassman-steps`). Внешний
schedule штатный, без произвольного фиксированного ограничения outer_steps.
Полные внутренние diagnostics и эффективные скалярные параметры сохраняются.
**Внутренний сертификат ADP отделён от внешней сходимости**: `all_inner_certified`
проверяет inner solves, а `converged` для внешнего цикла ADP остаётся unknown.
Остановки h_min/local_mass_limit не объявляются внешним сертификатом сходимости.

## Время, память и качество

Каждое обучение выполняется в новом процессе, последовательно; BLAS/OMP/MKL/BLIS
ограничены `--threads`, по умолчанию 1. Это холодные fits: первый вызов алгоритма
и его инициализация включены, повторный прогрев внутри измеряемого процесса
не выполняется. Время Python: perf_counter; R: proc.time elapsed с миллисекундным
разрешением. В fit_seconds входят preprocessing и OPG initialization, для dMAVE
также response kernels. Загрузка R/Python, пакетов, CSV и запись результата
исключены из fit_seconds, но включены в process_seconds. В R-reference/JIT и
готовом C++-ядре разные накладные расходы; вывод о наилучшем возможном времени
математического алгоритма из этого сравнения не следует.

Пиковая память — выборки Linux `/proc/<pid>/status` VmHWM с интервалом 25 мс,
включая интерпретатор, нативные библиотеки и данные. Это память процесса,
а не только Python heap; между последней выборкой и выходом пик может быть
пропущен. Лимит `--memory-mib` проверяется по RSS, с задержкой до интервала
опроса и возможным превышением; это не жёсткое резервирование памяти ядром ОС.
`--timeout` включает запуск процесса. При превышении лимита завершается группа
процесса, строка остаётся с timeout/memory_limit и последним измерением памяти.

Метрика восстановления в исходных координатах:

```
EDR = ||P_est-P_true||_F / sqrt(2m) = sqrt(mean(sin(theta)^2))
trace_score = mean(cos(theta)^2)
```

EDR=0 — идеальное совпадение, EDR=1 — ортогональные подпространства.
Используются устойчивые principal angles, без плотных d*d проекторов.
Также сохраняются средний/максимальный угол, max_sin_angle и ошибка
ортонормированности. Невалидный или неполноранговый базис — ошибка.
`recovered` означает валидный базис и EDR<=0.1 (`--recovery-threshold`),
сходимость учитывается отдельно. Все failures входят в знаменатель доли
восстановления; ещё не выполненные попытки явно отмечены в неполном отчёте.

CSV содержит mean/median/std/IQR/p95, bootstrap 95% интервалы медиан,
Wilson-интервалы recovery, числа ошибок/таймаутов/неизвестных certificates.
`paired.csv` сравнивает каждый метод с ADP по одинаковым seed: отношение времени
и разность EDR, с 2000 bootstrap-перевыборками пар. Количество совместно успешных
пар обязательно приводится. При выпадении методов эти интервалы условны по
совместному успеху, подвержены survivorship bias и не заменяют доли отказов.
Коррекция за множественные сравнения не выполняется. Десять повторов — минимум,
а не обещание узкого доверительного интервала; можно задать `--runs 30`.

## Выходы и возобновление

В `--output` сохраняются:

- `manifest.json`: весь протокол, версии Python/NumPy/SciPy/R/MAVE, BLAS,
  переменные потоков, источники и SHA256, определения методов и сходимости;
- `sources.zip` и `source/`: копия Python/R-исходников, из которой работают workers;
- `git-head.txt`, `git-status.txt`, `git-diff.patch`: состояние исходного checkout;
- `runs.jsonl`, `runs.csv`: сырые строки, включая все неудачи;
- `summary.csv`, `paired.csv`, `report.md`: сводки и парные сравнения;
- `fits/<case>-<seed>-<method>/`: базис, metadata, логи, R-траектории;
- `truth/`: истинные базисы, `completion.json`: полнота и число отказов;
- при `--plots`: `time-quality.png`, `recovery.png`;
- при `--keep-inputs`: сжатые исходные X,y,B каждого повтора в `inputs/`.

По умолчанию временные CSV удаляются после блока методов; данные полностью
восстанавливаются из seed и сохранённых исходников. Большая сетка с
`--keep-inputs` требует дополнительного места на диске.

```bash
# Возобновить: все исходные параметры должны совпадать
uv run --no-sync python -m experiments.r_sdr --profile full --runs 10 \
  --output benchmarks/results/outputs/r_sdr/full --plots --resume

# Перестроить отчёт без обучения
uv run --no-sync python -m experiments.r_sdr \
  --analyze benchmarks/results/outputs/r_sdr/full --plots

# Ограничить сравнение выбранными сценариями/методами
uv run --no-sync python -m experiments.r_sdr --profile full \
  --cases 'base,d-*,corr-*' --methods ADP,MAVE,MAVE-package,SIR,dMAVE,rMAVE \
  --runs 10 --output benchmarks/results/outputs/r_sdr/selected
```

Уже записанные исходы, включая неудачи, при resume не повторяются. Для новых
лимитов/параметров/исходников/окружения нужна новая директория: смешивание
протоколов отклоняется. При изменении рабочей копии исходный CLI можно запустить
из `OUTPUT/source` тем же абсолютным Python и с абсолютным `--output`.
Повреждённые/дублированные JSONL-строки вызывают ошибку; их нельзя молча удалять.
Не запускайте два исполнителя в одну директорию одновременно.
Код выхода 0 означает, что все попытки валидны; 1 — есть неудачные попытки;
2 — ошибка настройки, 130 — остановка пользователем. Низкое качество или
max_iterations сами по себе не превращаются в ошибку процесса.

Скалярные настройки ADP можно явно переопределить JSON-файлом через
`--adp-config config.json`, например `{"N_J": 500, "select_step": "last"}`.
Seed задаётся протоколом; custom kernels, GPU и experimental_centers для этого
сравнения не принимаются. Ограничения/параметры предварительно фиксируются в
manifest; автоматического подбора по истинному B нет.

## Проверки

```bash
uv run --no-sync pytest -q tests/test_r_sdr.py
uv run --no-sync ruff check experiments/r_sdr tests/test_r_sdr.py
uv run --no-sync pyright experiments/r_sdr
```

R-reference тест независимо проверяет SIR через плотную ковариацию, ошибки ранга,
потоковый QR и один density-MAVE шаг через полный стек LS по всем j,k;
обычный MAVE отдельно сравнивается с полным стеком при ambient-весах.
Изменение размера response-block не меняет решение в численной точности.
Python-проверки охватывают метрику/знаки/базис, воспроизводимость, минимум повторов,
timeout с сохранением лога, resume, парность статистики и разделение certificates.
