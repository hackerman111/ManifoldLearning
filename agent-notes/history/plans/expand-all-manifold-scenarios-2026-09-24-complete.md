# PLAN — расширить сетки всех manifold-сценариев

## Цель

Обеспечить ровно 7 уровней в каждой из 13 серий команды `experiments.manifold` и выбрать их так, чтобы значения доходили до пределов применимости/качества алгоритма.

## Вне задачи

- Менять estimator, код расчётов, solver, метрику или число повторов в каталоге.
- Запускать 2730 фактических fits; проверить новый объём через CLI dry-run.

## Известные свидетельства

- Все 13 серий имеют ровно 7 уровней; `overview` показывает полную сетку каждого manifold selector.
- Код manifold требует `d+1 < N_lin < n`, `index_dim + 1 <= N_J <= n`, `N_phi >= index_dim`, `index_dim < N_manifold < N_J`, `N_loc < n`, `sync_steps >= 1`; runner автоматически увеличивает `N_J` как минимум до `ceil(n/N_loc)`.
- Поэтому `manifold-n` фиксирует `N_J=36`; `manifold-nloc` начинается с 10 при `n=240,N_J=24`, а `manifold-centers` — с 12, чтобы effective config не сливал разные уровни.
- `runs.csv`/suite reports уже записывают качество, recovery, ошибки и причины отказа; 30 повторов на каждый уровень позволяют оценить частоту срыва. Семь точек только локализуют переход между соседними уровнями, не дают непрерывной оценки порога.

## Инварианты

- Меняется только состав экспериментальной сетки и выбор исходных точек профиля.
- Сохраняются исходные уровни, где это совместимо с ровно семью точками; дополнения покрывают нижнюю/верхнюю границу, а не заполняются только равномерно.
- Все manifold-серии остаются доступными под прежними selectors, с теми же пятью повторами по умолчанию.
