# PLAN — диагностические бенчмарки ADP

## Цель

На основе существующего `experiments/` дать воспроизводимый короткий протокол для single, multi и manifold, который показывает качество обучения, режимы отказа и лучшие **среди проверенных** параметры запуска. Сравнивать параметры на парных данных; выбирать кандидат на одних seed и показывать результат на других.

## Вне задачи

- Менять production estimator, solver, публичный API или прежние каталоги/артефакты.
- Утверждать глобальный оптимум, переносимость между режимами или статистическую уверенность по smoke/малому числу seed.
- Строить полный декартов поиск гиперпараметров или автоматически применять найденную конфигурацию.

## Известные свидетельства и гипотеза

- `experiments/runner.py` уже сохраняет все fits, качество/порог, convergence, failure mode, время, `tracemalloc`, trace и конфигурацию; `data.py` поддерживает общие случайные потоки по `common_random_fields`.
- Текущие каталоги охватывают множество отдельных факторов, но `overview.md` и `phase_summary.csv` не выбирают конфигурацию на отдельных seed и не проверяют её на других seed.
- Гипотеза: парные локальные варианты параметров на базовом, шумном и коррелированном/малом режиме выявят слабые зоны и дадут условную, проверяемую рекомендацию быстрее полного перебора.

## Инварианты и классификация

- Все параметры остаются явными `ESTIMATOR`-вариантами только внутри benchmark; production default не меняется.
- Single: `abs(cos)` выше лучше; multi: `trace_score` выше лучше; manifold: ошибка локальных проекторов ниже лучше. Recovery требует и сходимость, и порог качества. Ошибки входят в знаменатель.
- Разделение seed по run index без пересечения; у вариантов внутри одного сценария совпадают входные данные и случайные потоки. Не смешивать метрики семейств, не смешивать разные сценарии при выборе параметра.
- Записывать фактические `effective_config`, git/dirty, версии, BLAS/threads, точные сценарии, seed split, правила выбора. Обозначать `tracemalloc` как Python allocations, не RSS.
