# Подробные multi-index эксперименты 1–5

## Цель

Добавить пять крупных селекторов `mi-1`–`mi-5`, которые исследуют границы
работоспособности multi-index ADP с той же детализацией, что numbered
single-index эксперименты. Существующие узкие селекторы `mi-*` сохраняются для
совместимости.

Solver и estimator не меняются. Новые формулы генерации данных изолированы в
точках новых экспериментов и явно записываются в артефакты.

## Общий протокол

Во всех пяти экспериментах:

- данные `X` имеют форму `(n, d)`;
- истинный базис `B` имеет форму `(d, m)` и ортонормальные столбцы;
- базовая link-функция — `multi_additive` с `link_scale=3`, если сетка не
  задаёт другой вариант;
- полный профиль содержит 25 независимых повторов;
- smoke-профиль содержит одну уменьшенную точку и один повтор;
- внутренний AO получает `solver_max_steps=5`;
- качество измеряется нормированной проекторной ошибкой;
- recovery означает численную сходимость и `projector_distance <= 0.1`;
- сохраняются четыре взаимоисключающих исхода `numerical_failure`,
  `nonconverged`, `converged_bad_quality`, `recovered`.

`--runs` по-прежнему может переопределить число повторов. Все A/B build
получают одни и те же сгенерированные данные.

## Сетки

### `mi-1`: граница по размеру задачи

```text
d = (5, 25, 50)
n_over_d = (1.15, 1.5, 2, 3, 4, 5, 6, 7, 8, 9, 10)
m = 2
```

Итого 33 точки и 825 fit. Это multi-index аналог эксперимента 2. Малые
`n/d` намеренно включены для наблюдения перехода от неработающего режима к
восстановлению.

### `mi-2`: шум

```text
d = (25, 50)
n_over_d = (2, 5, 10)
sigma_eps = (0, 0.2, 0.316, 0.4, 0.5, 0.6, 0.707, 0.8, 1, 1.414, 2)
m = 2
```

Итого 66 точек и 1650 fit. Сетка сохраняет диагностические уровни условия
`n / sigma_eps**2 >= 20 d` и добавляет соседние точки перехода.

### `mi-3`: коррелированные признаки

```text
d = (25, 50)
n_over_d = (2, 5, 10)
rho_corr = (0, 0.25, 0.5, 0.75, 0.9, 0.95, 0.98, 0.99)
m = 2
```

Итого 48 точек и 1200 fit. Генератор сохраняет AR(1)-ковариацию
`rho_corr ** abs(i - j)`.

### `mi-4`: масштаб признаков

```text
d = (25, 50)
n_over_d = (2, 5, 10)
sigma_x = (0.125, 0.25, 0.5, 1, 2, 4, 8)
m = 2
```

Итого 42 точки и 1050 fit. Link получает нормированные проекции

```text
Z = (X @ B) / sigma_x
```

после чего сигнал стандартизуется существующим способом. Поэтому при одном
seed меняется только масштаб `X`, а `Y` и истинное подпространство совпадают в
пределах обычной погрешности `float64`. Это отдельный experimental data-design,
а не изменение estimator.

### `mi-5`: размер подпространства и link

```text
d = (25, 50)
n_over_d = (2, 5, 10)
m = (2, 3, 5, 7, 10)
link = (multi_additive, multi_multiplicative)
link_scale = (1, 2, 3, 4)
```

Итого 240 точек и 6000 fit. `d=100` не используется. Для `m > 2`
сохраняется реализованное продолжение link через дополнительные координаты
`sum_{r=3}^m z_r**2 / r`.

Все пять сеток вместе содержат 429 точек и 10 725 fit.

## Явные параметры генерации

В `ExperimentPoint` добавляются:

- `normalize_link_by_sigma_x: bool = False`;
- `basis_pool_dim: int | None = None`.

Существующий single-index эксперимент 5 переводится с проверки selector на
`normalize_link_by_sigma_x=True` без изменения его данных. `mi-4` использует
тот же явный режим для multi-index проекций.

В `mi-5` каждая полная точка имеет `basis_pool_dim=10`. Генератор создаёт один
ортонормальный базис `(d, 10)` и берёт первые `m` столбцов. Поэтому истинные
подпространства для `m={2,3,5,7,10}` вложены. Smoke-точка использует
`basis_pool_dim=3` при `d=4`, `m=2`.

Для других экспериментов `basis_pool_dim=None` сохраняет существующую схему
генерации базиса `(d, m)` и прежние результаты.

## Common random numbers

Seed bundle строится из selector, остальных параметров точки и номера
повтора, исключая только исследуемые факторы:

- `mi-2`: `sigma_eps`;
- `mi-3`: `rho_corr`;
- `mi-4`: `sigma_x`;
- `mi-5`: `index_dim`, `link`, `link_scale`.

Для одинаковых `(selector, d, n_over_d, run)` это обеспечивает:

- в `mi-2` одинаковые `X`, `B` и стандартный noise draw;
- в `mi-3` одинаковые исходные нормальные числа, `B` и noise draw;
- в `mi-4` одинаковые базовые признаки, `B`, noise draw и `Y`;
- в `mi-5` одинаковые `X`, полный базис `(d, 10)` и noise draw для всех
  значений `m`, link и частоты.

Другие эксперименты сохраняют прежнюю seed-схему. Поля common-random
записываются в `series.json`.

## Фазовая отчётность

Для `mi-1` сохраняется обычная фазовая агрегация по `(d, n_over_d, build)`.

Для `mi-2`, `mi-3`, `mi-4` основными condition fields становятся
соответственно `sigma_eps`, `rho_corr`, `sigma_x`. Используется существующая
условная агрегация и layout:

- X — condition level;
- Y — `n_over_d`;
- одна строка на `(build, d)`;
- столбцы — convergence, quality pass и recovery;
- отдельный PNG показывает четыре failure mode.

Для `mi-5` основной condition field — `index_dim`, а
`condition_group_fields=("link", "link_scale")`. В `phase_summary.csv` и
`boundary.csv` строки группируются по
`(d, n_over_d, index_dim, link, link_scale, build)`. Поля `link` и
`link_scale` записываются отдельными CSV-колонками.

Для каждой из восьми пар `(link, link_scale)` строятся отдельные:

- `phase_diagram-<link>-s-<scale>.png`;
- `failure_modes-<link>-s-<scale>.png`.

Внутри каждого файла X — `m`, Y — `n/d`, строка соответствует `(build, d)`.
Итого `mi-5` создаёт 16 стратифицированных phase/failure PNG и не строит
агрегированный график, смешивающий разные link или частоты.

Существующие `runs.csv`, `summary.csv`, `summary.md`, одномерные PNG и сырые
trace сохраняются. Схема manifest повышается до версии 4.

## Валидация и ошибки

- `basis_pool_dim` должен быть целым, удовлетворять
  `index_dim <= basis_pool_dim <= d` и использоваться только в multi-mode;
- `normalize_link_by_sigma_x` должен быть boolean;
- `condition_group_fields` должны быть непустыми уникальными именами полей
  `ExperimentPoint`, отличными от основного `condition_field`;
- основной condition level должен быть конечным числом;
- отсутствие обязательной CSV-колонки прекращает отчёт с `ValueError`;
- неуспешный fit остаётся в `runs.csv` и участвует в failure-rate.

## Проверка

Фокусные тесты проверяют:

- селекторы `mi-1`–`mi-5`, размеры `33`, `66`, `48`, `42`, `240`, 25
  повторов и threshold `0.1`;
- правильные condition/common-random/group fields;
- одинаковые seed bundles внутри парных профилей и разные bundles между
  разными `(d, n_over_d)`;
- ортонормальность полного базиса и вложенность оценочных целей для всех `m`;
- точное масштабирование `X` и совпадение `Y`, `B` в `mi-4`;
- отсутствие смешивания `(link, link_scale)` в фазовых CSV;
- создание 16 стратифицированных PNG `mi-5`;
- сохранение отчётов numbered single-index экспериментов.

После фокусных тестов выполняются Ruff, Pyright, полный pytest,
`uv lock --check`, импорт пакета и smoke-запуски `mi-1`–`mi-5`.

## Вне scope

Не добавляются внешние методы, adaptive runner, multiprocessing, изменение
kernel, bandwidth, regularization, tensor law, direction law или estimator по
умолчанию. Узкие селекторы `mi-*` не удаляются и не переименовываются.
