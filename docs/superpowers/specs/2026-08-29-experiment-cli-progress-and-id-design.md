# Progress и ID запуска экспериментов

## Цель

Сгруппировать результаты одного запуска `python -m ADP.experiment` в общей
папке и показывать ход выполнения отдельных fit через `tqdm`.

## Контракт сохранения

CLI один раз создаёт читаемый timestamp-ID с точностью до микросекунд и
передаёт его всем выбранным экспериментам. Результаты сохраняются так:

```text
<output-dir>/<experiment-id>/<selector>/
```

Внутри selector-папки остаются существующие `series.json`, `runs.csv`,
агрегаты и графики. Поле `experiment_id` в `series.json` совпадает с именем
общей папки. Прямой вызов `Experiment.run()` без ID создаёт новый ID сам.
Переданный через Python API ID должен быть непустым безопасным именем одного
компонента пути.

## Прогресс

CLI включает один progress bar на selector. Его `total` равен числу точек,
умноженному на число повторов и число builds. Счётчик увеличивается после
записи каждой строки результата, в том числе при численной ошибке. Прямые
вызовы Python API по умолчанию остаются без вывода прогресса.

`tqdm` добавляется как runtime-зависимость, поскольку стандартный CLI должен
работать без скрытого optional extra.

## Совместимость и проверка

Формат файлов результата и обработка статусов не меняются. Фокусные тесты
проверяют общий ID для нескольких selectors, новую структуру пути, поле
`experiment_id` в manifest и включение progress из CLI.
