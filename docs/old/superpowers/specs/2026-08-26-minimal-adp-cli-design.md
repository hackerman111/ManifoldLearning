# Минимальный CLI для ADP

## Цель

Добавить автономный CLI для быстрого воспроизводимого запуска single- и
multi-index ADP на синтетических данных. CLI ничего не сохраняет и печатает
результат, качество, время и память по стадиям.

## Интерфейс

Основной запуск:

```bash
uv run python -m ADP.cli --mode single
uv run python -m ADP.cli --mode multi --index-dim 2
```

Используется только `argparse`. CLI принимает:

- данные: `mode`, `n`, `d`, `index_dim`, `noise`, `data_seed`;
- все поля `ADP_Config`: `seed`, `N_loc`, `N_lin`, `N_J`, `N_phi`,
  `outer_steps`, `lambda_penalty`, `local_ridge`, `kernel`, `a`, `h_min`,
  `batch_size`, `index_init`;
- LSMR: `solver_tol`, `solver_max_steps`, `theta`, `trust_radius`,
  `lsmr_maxiter`.

`kernel` принимает встроенный `epanechnikov` или доверенный путь
`module:function`. Сокращения аргументов отключены.

## Данные и воспроизводимость

`X`, истинный индекс и шум создаются независимыми потоками
`np.random.default_rng`, полученными через `SeedSequence(data_seed)`.
Алгоритмическая случайность управляется отдельным `ADP_Config.seed`.

Для single-index:

\[
z = X\beta, \qquad Y = \sin(z) + 0.25z^2 + \varepsilon.
\]

Для multi-index формула применяется покомпонентно к `Z = XB`, после чего
компоненты суммируются. Столбцы `B` ортонормальны. Такая нелинейность позволяет
задействовать все координаты целевого подпространства без реестра link-функций.

Инициализация `local` и `random` использует существующие функции движка.
`pilot` разрешён только для multi-index и сохраняет существующее требование
установленного `scikit-learn`.

## Численный поток

`ADP_Solver` получает минимальное расширение для двух явных путей:

- single использует `generate_proj`, `calculate_weight` и векторный LSMR;
- multi использует `generate_multi_proj`, `calculate_multi_weight` и
  матричный LSMR.

Общие расчёты полосы, статистик и уменьшения `h` не копируются в CLI.
Multi-index канонизирует базис и локальные коэффициенты без изменения fitted
values, затем получает малые собственные значения для следующей локализации.
Это `EXACT`-преобразование фиксированной sketch-задачи. Новый multi-режим
является отдельным явно выбранным вариантом и не меняет default single-режим.

Размеры следуют контрактам проекта: `X (n, d)`, single index `(d,)`, истинный
multi-basis `(d, m)`, solver multi-index `(m, d)`, `I (J, P)`, `U (J, P, d)`.
Веса остаются ленивыми блоками `(B, n)`.

## Профилирование и вывод

Собираются стадии `data`, `initialization`, `bandwidth`, `directions`,
`statistics`, `solver`, `update`, `total`. Повторяющиеся стадии агрегируются:
время суммируется, пик памяти берётся по максимуму.

- время: `time.perf_counter()`;
- память стадии: дополнительный пик `tracemalloc`;
- память процесса: общий Linux RSS high-water mark через `resource.getrusage`.

Вывод явно называет метод измерения: `tracemalloc` не считается полной оценкой
всех native-аллокаций. Численные ядра не печатают; CLI выводит собранный
`profile_` после `fit`.

CLI также печатает эффективные параметры, форму результата и качество:
`abs(beta_true @ beta_hat)` для single или ошибку
`sum(sin(theta_j)^2)` из `multiindex.tex` для multi.

## Ошибки

На границе CLI проверяются конечность и согласованность параметров, включая
`n > d + 1`, `1 <= index_dim < d` и `N_phi > index_dim` для multi.
Ошибки аргументов завершаются кодом `2`, численные ошибки — кодом `1`, успех —
кодом `0`. Численный сбой не заменяется предыдущим индексом.

## Проверка

Один `tests/test_cli.py` проверяет полный разбор параметров и два малых
детерминированных запуска single/multi. Проверяются конечные результаты,
формы, ортонормальность multi-базиса, sign/subspace-invariant метрики и наличие
стадий профиля. Затем запускаются настроенные Ruff, Pyright и Pytest.

Не добавляются experiment-файлы, CSV/NPZ, графики, resume, сторонний CLI-фреймворк
или отдельная система логирования.
