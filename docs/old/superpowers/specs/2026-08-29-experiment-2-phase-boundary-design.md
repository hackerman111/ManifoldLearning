# Граница работоспособности эксперимента 2

## Цель

Модифицировать эксперимент `2` так, чтобы он показывал не только качество и
время, но и границу, на которой ADP одновременно:

1. численно сходится;
2. восстанавливает single-index направление с
   `cosine_abs >= 0.9`.

Основная сетка исследует текущие настройки по умолчанию. Отдельные rescue-
запуски проверяют, вызван ли отказ ограничением решателя или параметрами
estimator. Численный алгоритм, генератор данных и формула estimator в рамках
этой работы не меняются.

## Классификация изменения

Добавление производных статусов, агрегатов и графиков является `EXACT`: оно
не влияет на оценку. Увеличение `solver_max_steps` в numerical rescue является
явным `NUMERICAL`-вариантом. Изменение `N_loc` или `N_phi` является отдельным
`ESTIMATOR`-вариантом и не становится новым значением по умолчанию.

## Основная сетка

Эксперимент `2` сохраняет текущие 44 точки:

- `d in {5, 25, 50, 100}`;
- `n_over_d in {1.15, 1.5, 2, 3, 4, 5, 6, 7, 8, 9, 10}`.

Полный профиль использует 25 независимых повторов. CLI-аргумент `--runs`
по-прежнему может явно переопределить это число. Baseline запускается с явно
записанными аргументами `--solver cg --cg-maxiter 500`; значение
`solver_max_steps=3` остаётся настройкой build. Глобальный CLI-default solver
не меняется.

## Исход одного запуска

Существующее поле `status` сохраняется без изменения. Для нового запуска в
`runs.csv` добавляются поля:

- `convergence_pass`: истинно только при
  `diagnostics["converged"] is True`;
- `quality_pass`: истинно только для конечного `cosine_abs >= 0.9`;
- `recovered`: конъюнкция двух предыдущих условий;
- `failure_mode`: один взаимоисключающий исход.

Приоритет `failure_mode`:

1. `numerical_failure` для исключения, нечислового результата или уже
   зарегистрированной численной ошибки;
2. `nonconverged` для корректного конечного результата без подтверждённой
   сходимости;
3. `converged_bad_quality` для сошедшегося результата с `cosine_abs < 0.9`;
4. `recovered` для сошедшегося результата с `cosine_abs >= 0.9`.

Метрика, направление сравнения и порог записываются в `series.json`. Это не
позволяет молча смешать серии, построенные с разными определениями успеха.

## Двумерные агрегаты

Отчёт группирует строки одновременно по `(d, n_over_d, build)`. Он не
усредняет один фактор по уровням второго. Для каждой ячейки записываются:

- число запусков;
- число запусков с конечным качеством;
- доли `convergence_pass`, `quality_pass`, `recovered`;
- доли четырёх `failure_mode`;
- медиана и квантили качества;
- 95% Wilson interval для трёх бинарных долей.

Wilson interval вычисляется напрямую без новой зависимости. Для
`convergence_pass` и `recovered` знаменателем является число всех назначенных
запусков: numerical failure является отказом алгоритма. Для `quality_pass`
знаменателем является отдельно записанное число запусков с конечным
качеством. Пустые ячейки и ячейки без конечного качества сохраняются как
пропуски, а не как наблюдаемое плохое качество.

## Артефакты

К существующим файлам добавляются:

- `phase_summary.csv` — одна строка на `(d, n_over_d, build)`;
- `boundary.csv` — диагностические точки для rescue;
- `plots/2/phase_diagram.png` — `P(converged)`, `P(quality_pass)` и
  `P(recovered)` для каждого build;
- `plots/2/failure_modes.png` — доли четырёх взаимоисключающих исходов.

`boundary.csv` включает:

- `transition`, если `0.2 <= P(recovered) <= 0.8`;
- `numerical`, если `P(quality_pass) >= 0.8`, но
  `P(convergence_pass) < 0.8`;
- `estimator`, если `P(convergence_pass) >= 0.8`, но
  `P(quality_pass) < 0.8`.

Одна точка может получить несколько причин, записанных в одном стабильном
поле через запятую.

## Rescue-протокол

Rescue выполняется последовательно после основной сетки; отдельный
адаптивный планировщик не добавляется.

### Numerical rescue

Из `boundary.csv` берутся точки с причиной `numerical`. На 10 tuning-семенах
с общими данными сравниваются `solver_max_steps in {3, 6, 12}`. Выбирается
наименьшее значение с максимальной долей `recovered`. При равенстве
используется меньшее wall-clock время. Выбранный вариант сравнивается с
defaults на 25 новых парных семенах.

### Estimator rescue

После numerical rescue берутся точки с причиной `estimator`. На 10 новых
tuning-семенах сравнивается сетка:

- `N_loc in {10, 20}`;
- `N_phi in {10, 20}`.

Победитель максимизирует долю `recovered`; затем используются медианное
качество и время как последовательные tie-breakers. Defaults и победитель
сравниваются на 25 новых парных семенах. `lambda_penalty` остаётся равным
`0.05`; его сетка добавляется только отдельным последующим экспериментом,
если ни один кандидат не улучшает recovery.

Tuning- и confirmation-семена не пересекаются. Все кандидаты внутри одного
этапа получают одинаковые данные, центры, направления и инициализацию;
использование common random numbers здесь является явной частью протокола.
Результаты rescue хранятся отдельными сериями и не подменяют baseline.

## Совместимость

Существующие `summary.csv`, `summary.md`, графики и `status` сохраняются.
Старые `runs.csv` без новых булевых полей читаются по `status` и
`solver_diagnostics`:

- `success` означает сходимость только при явном
  `solver_diagnostics["converged"] is True`;
- `nonconverged` означает её отсутствие;
- `numerical_failure` сохраняет высший приоритет.

Если явного признака сходимости нет, значение остаётся неизвестным и такая
строка не может быть `recovered`.

Для старой серии порог должен быть передан явно при повторном построении
phase-отчёта; отсутствующий порог не угадывается молча.

## Проверка

Фокусные тесты проверяют:

- 44 точки основной сетки и 25 повторов полного профиля;
- приоритет четырёх исходов, включая нечисловое качество;
- отдельную агрегацию всех `(d, n_over_d)` без смешивания размерностей;
- Wilson interval на известных малых счётчиках;
- создание `phase_summary.csv`, `boundary.csv` и двух PNG;
- чтение старого `runs.csv` без новых колонок;
- одинаковые seed bundles для парных rescue-кандидатов;
- непересекающиеся tuning- и confirmation-семена.

После фокусных тестов выполняются настроенные в `pyproject.toml` Ruff,
Pyright и pytest.

## Вне scope

Не добавляются автоматическое уточнение сетки, multiprocessing, новый формат
конфигурации builds, подбор `lambda_penalty` и изменения solver/estimator по
умолчанию.
