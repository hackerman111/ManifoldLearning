# CuPy-статистики и LSMR для ADP

## Цель и границы

Добавить явный GPU-режим для single- и multi-index ADP. Режим переносит на
CuPy только вычисление статистик и встроенный LSMR. Генерация данных,
центров, направлений и весовых блоков остаётся на CPU.

Вне области изменения: автоматический выбор устройства, молчаливый fallback
на CPU, VarPro, смешанная точность, перенос вычисления весов и новая GPU
телеметрия памяти.

## Публичный интерфейс

`ADP_Config` получает поле `gpu: bool = False`. CLI получает флаг `--gpu`.
Без флага поведение и типы CPU-пути не меняются.

GPU-режим разрешён только со встроенным LSMR. Сочетание
`--gpu --solver varpro` и передача пользовательского solver-а в модель с
`gpu=True` завершаются до `fit` понятной ошибкой.

## Доступность CUDA

CuPy остаётся необязательной зависимостью и импортируется лениво. При
`gpu=True` модель до тяжёлой инициализации проверяет:

- возможность импортировать CuPy;
- наличие хотя бы одного CUDA-устройства;
- возможность инициализировать CUDA runtime.

Любая ошибка приводит к `RuntimeError` с причиной. Автоматического перехода
на CPU нет.

## Поток данных статистик

GPU-функция сохраняет существующий контракт упорядоченных блоков весов.
`X`, `Y` и `Phi` копируются на устройство один раз за внешнюю итерацию,
каждый CPU-блок `W` — один раз перед обработкой.

Порог local/dense остаётся точным и определяется по фактическим ненулевым
элементам CPU-блока. Формулы `_local_block`, `_dense_block` и
`_normalized_residual` получают NumPy/CuPy backend и не дублируются.

Результат `ADP_Statistics` хранит `I` и `U` как `cupy.ndarray`, чтобы не
копировать главный объём обратно перед solver-ом. Малые поля `mass`, `mean`,
`n_eff` и `eta` возвращаются как NumPy-массивы для совместимости модели и
trace. Конечная host-копия малых полей синхронизирует статистическую стадию,
поэтому её wall time включает завершение CUDA-работы.

## GPU LSMR

Существующий `LSMR.solve` выбирает backend по типу `statistics.U`:

- NumPy-массивы используют текущие SciPy `LinearOperator` и `lsmr`;
- CuPy-массивы используют `cupyx.scipy.sparse.linalg.LinearOperator` и
  `lsmr`.

Общие single/multi helper-ы принимают backend `xp`; отдельная копия solver-а
не создаётся. `I`, `U` и рабочие массивы остаются на GPU во всех внутренних
итерациях. На CPU возвращаются только итоговый index, coefficients и
diagnostics. Эта копия синхронизирует solver stage.

Числа остаются `float64`. Формы, критерии остановки, регуляризация и
ориентация индекса совпадают с CPU-путём.

## CLI и эксперименты

`--gpu` попадает в effective `ADP_Config` и сохраняется вместе с остальными
requested/effective параметрами. `auto` и `lsmr` допустимы; `varpro`
отклоняется при валидации experiment-а до запуска job.

## Проверка

- CPU regression: весь существующий pytest остаётся зелёным.
- CLI/config: `--gpu` явно включает поле, default остаётся `False`, VarPro
  отклоняется.
- Без CUDA: прямой GPU-вызов выдаёт ожидаемый `RuntimeError`, а не fallback.
- При доступной CUDA: статистики CPU/GPU сравниваются по всем полям;
  single/multi LSMR сравниваются с учётом знака или проектора. Эти тесты
  автоматически пропускаются, если CUDA недоступна.

Текущая машина не видит CUDA-устройство, поэтому здесь можно доказать CPU
регрессию и error path, но нельзя честно заявить GPU parity или ускорение до
запуска на исправном NVIDIA runtime.
