# Hybrid-солверы multi-index ADP и manifold

Оптимизация от 2026-09-15: [отсев trust-проб, пакетный refit и измерения](hybrid_optimization.md).
Измерения ниже описывают первоначальную реализацию HYBRID; новый отчёт
сравнивает обновлённый HYBRID именно с этой реализацией.

Реализация: `ADP/solver/HYBRID.py`. Новый режим выбирается явно;
исходные LSMR и CG остаются доступными. Формулы статистик, веса, направления,
инициализация, штрафы и внешний алгоритм в этой работе не изменены.
Работа выполнена поверх предыдущей незакоммиченной оптимизации ADP.

## Выбор метода

Для multi-index сохраняется HPAO и задача коррекции

\[
\min_\Delta \|A\Delta-r\|^2+\lambda\|\Delta\|^2,
\qquad A(B)_j=\sqrt{mass_j}\,U_jB^TL_j.
\]

- При небольшой системе строится ограниченный по памяти joint design и его
  SVD. В течение одного HPAO-шага меняется только `lambda`: одна факторизация
  обслуживает все пробы штрафа. Новый набор коэффициентов инвалидирует кэш.
  Коэффициенты спектрального решения — `s/(s²+lambda)`.
- Для больших систем используется расширенный оператор `[A;sqrt(lambda)I]`
  и LSMR с правым диагональным масштабированием. Масштабирование применяется
  и к штрафу, поэтому регуляризатор в исходных координатах сохраняется.
  При `lambda=0` правое масштабирование отключено для сохранения minimum-norm
  коррекции в исходной метрике.
- Принятие шага, trust radius, нормировка, gauge compensation, локальный
  refit и проверка исходного нормального остатка остаются в HPAO.
  Неуспешный stop-код LSMR не принимается даже при малой коррекции.

Для manifold решается исходная задача при фиксированных локальных slopes:

\[
\min_B\sum_j mass_j w_j\|I_j-U_jB^TL_j\|^2
 +\lambda\operatorname{tr}(BCB^T),\quad
C=I-\sum_j\bar w_jP_j^TP_j.
\]

- Небольшая система решается SVD расширенной LS-матрицы. Квадратный корень
  `C` вычисляется через тонкую SVD фактора из `sqrt(w_j) P_j`.
- Большая система сначала решается joint PCG. Предобуславливатель хранит
  `(d,m,m)` блоки: для каждого признака учитываются перекрёстные члены между
  индексами. Каждый блок применяется через малое eigendecomposition,
  без явного обращения. Матрица normal equations не материализуется.
- Если PCG не сошёлся либо не прошёл сертификат, запускается расширенный
  LSMR. Предыдущий базис не выдаётся вместо неудачного решения. Отказ обоих
  методов приводит к `RuntimeError`. Итерации обеих попыток суммируются.
- Принимается только конечное решение с проверенным остатком исходной
  manifold-задачи, включая исходный penalty, а не только его sqrt-фактор.

Выбор PCG для большой manifold-задачи намеренный: на записанной точке
`d=150,m=2` первоначальная версия с обязательным augmented LSMR занимала
около 2,9 s против 0,7 s у CG. Normal equations ухудшают обусловленность;
этот недостаток компенсируется проверкой результата и резервным LSMR,
но исчезновение всех численных отказов не обещается.

Классификация: **NUMERICAL** — SVD, масштабирование, квадратный корень penalty
и блочный предобуславливатель сохраняют целевой функционал; **APPROXIMATE** —
итерационные методы имеют конечные допуски и изменённый способ решения.
Новый режим изолирован параметром `hybrid`; estimator не подменяется.

## Использование

```python
from ADP.solver.HYBRID import solve

result = solve(
    index_init,
    U,
    I,
    mass=mass,
    lambda_prox=0.05,
    max_steps=3,
    tol=1e-6,
)
index = result.index
print(result.diagnostics)
```

Здесь `index_init=(m,d)`, `U=(J,P,d)`, `I=(J,P)`, `mass=(J,)`.
Single-index в новом режиме намеренно не поддерживается.

```python
from ADP import ADP_Manifold

model = ADP_Manifold(
    index_dim=2,
    solver="hybrid",
    cg_tol=1e-8,
    cg_maxiter=1000,
)
model.fit(X, Y)
```

В manifold сохранены прежние имена `cg_tol` и `cg_maxiter`: они задают
допуск сертификата и предел каждой итерационной попытки нового режима.
Резервный LSMR может потребовать вторую попытку до этого же лимита.

CLI поддерживает `--solver hybrid` в `--mode multi` и `--mode manifold`,
в том числе через `ADP.cli.experiment` для соответствующих экспериментов.

```bash
rtk proxy uv run --no-sync python -m ADP.cli --mode multi --solver hybrid --n 1000 --d 100 --index-dim 2 --N_J 100 --N_phi 20 --N_loc 20 --N_lin 150 --outer_steps 3 --solver-max-steps 3
```

Параметры `dense_max_unknowns` и `dense_max_bytes` доступны в Python;
CLI использует `--dense-max-unknowns` и `--dense-max-bytes`.
По умолчанию: не более 256 неизвестных и оценка рабочей памяти не более
64 MiB. Ноль отключает плотную ветку. Это консервативный dispatch между
проверенными режимами 200, 300 и 1000 неизвестных, не универсальный crossover.
Оценка включает вход и несколько рабочих копий LAPACK, но не является
ограничителем RSS всего процесса.

Плотный design требует `O(J*P*m*d)` памяти; он создаётся только после проверки
бюджета. SVD-факторизация переиспользуется при изменении `lambda`.
В большой multi-index ветке сверх `U` нужны массивы порядка `J*d+m*d+J*P`.
Для отсева trust-проб дополнительно используются не более 32 векторов
длины `m*d`; их рабочая память ограничивается `dense_max_bytes`.
Нулевой бюджет отключает как SVD-dispatch, так и этот вспомогательный отсев.
В PCG manifold дополнительно хранятся `(d,m,m)` блоки. Dense `(m*d,m*d)`
нормальная матрица нигде не строится. Dense `(d,d)` sqrt-factor penalty
существует только в ограниченной малой SVD-ветке.

Диагностика multi-index: `linear_backends`, `linear_solves_total`,
`linear_iterations_total`, stop-код, исходный нормальный остаток, принятые
шаги и `converged`. Для прямого SVD stop-код равен нулю; интерпретировать его
следует вместе с именем backend, а не как код SciPy LSMR.
`linear_screened_trials` считает пробы, отклонённые до LSMR;
`linear_screening_matvecs` — пары действий `A`/`A*`, затраченные на отсев.
Manifold trace содержит `linear_iterations`, `linear_relative_residual_max`,
`dense_solves`, `pcg_solves`, `fallback_solves`. Старые `cg_*` поля относятся
только к старому режиму CG.

## Измерения

Intel i5-12400F, один BLAS-поток, Python 3.13.12, NumPy 2.5.2,
SciPy 1.18.1, float64. Сравнивается текущий оптимизированный LSMR/CG
с новым hybrid, а не с кодом до предыдущей оптимизации.
Парные запуски используют одни данные и три seed, порядок A/B чередуется.
Wall-clock полного runner включает его `tracemalloc`; это не изолированный
аппаратный стенд. RSS измеряется high-water отдельного процесса.

Медианы трёх запусков (`benchmark_outputs/hybrid_solvers_verified`):

| Задача | Старое полное время, s | Hybrid, s | Старый solver, s | Hybrid solver, s |
|---|---:|---:|---:|---:|
| multi: n=1000,d=100,J=100,P=20,m=2 | 1,848 | 0,731 | 1,398 | 0,278 |
| multi: n=1000,d=100,J=100,P=20,m=10 | 4,323 | 2,680 | 3,855 | 2,225 |
| manifold: n=600,d=150,J=20,P=30,m=2 | 0,297 | 0,311 | 0,291 | 0,305 |

Для multi `m=2` солвер ускорился примерно в 5 раз, обучение — в 2,5 раза;
для `m=10` — в 1,7 и 1,6 раза соответственно. Максимальная разница
метрики качества — `8,3e-10` и `8,6e-9`. RSS около 89–94 MiB.
В большой manifold-точке скорость сопоставима (hybrid примерно на 5% медленнее),
RSS около 74 MiB, разница качества не более `5,7e-6` при допуске `1e-6`.
Поэтому универсально самым быстрым этот солвер не называется.

В небольших успешных manifold-точках SVD давала ускорение полного обучения
примерно 1,2–1,6 раза; исходный нормальный остаток был порядка `1e-15`
против `1e-6` у CG. Эти числа относятся только к успешным парам: часть seed
отказала на локальной инициализации или восстановлении EDR-ранга **у обоих**
методов. Отказы не удалены из результатов. Увеличение N_lin устраняет не все
ранговые проблемы внешнего алгоритма. Новый солвер не обещает исправить
неинформативные локальные статистики или улучшить статистическое качество.

## Воспроизведение

```bash
rtk proxy uv run --no-sync python -m benchmarks.hybrid_solvers --output /tmp/hybrid_compare --cases multi2 multi10 manifold150
rtk proxy uv run --no-sync python -m benchmarks.hybrid_solvers --output /tmp/hybrid_manifold --cases manifold20 manifold_adaptive --feasible
rtk proxy uv run --no-sync pytest tests/test_hybrid.py tests/test_cli.py
```

Скрипт создаёт отдельные процессы, фиксирует BLAS-потоки и сохраняет JSON
с параметрами, seed, исходной версией, dirty state, хэшами исходников,
версиями библиотек, временем, RSS, диагностикой и ошибками. Базисы сохранены
в NPY. Все настройки данных, ядра и внешнего алгоритма берутся из этих JSON.
Предварительные и окончательные замеры лежат раздельно в
`benchmark_outputs/hybrid_solvers*` и не перезаписывают друг друга.

Проверки охватывают плотный augmented reference, прямое/сопряжённое действие,
SPD-предобуславливатель, исходный residual, ridge 0/малый/большой,
неравные массы, почти коллинеарные признаки, поворот базиса, warm start,
памятный dispatch, предел итераций, fallback и отказ обоих методов,
а также запуск обоих режимов через CLI.
