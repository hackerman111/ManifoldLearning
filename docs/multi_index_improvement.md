# Multi-index: локализация, память и адаптивный ridge

Исходная версия: `42b4f124bf599c669cfd18b62d1c842118ebf536`, ветка
`Astra-hard-optim`. Измерения относятся к рабочему патчу поверх этой версии.
Для идей исследован также `main` (`80669d7ebe5adfaf60e8c9505e2aa58f5d258806`):
`select_optimal_alpha` и `tex/smart_search.md`.

## Формулы и границы изменений

При фиксированных локальных коэффициентах сохранена совместная задача

\[
\min_B\sum_j mass_j\|I_j-U_jB^TL_j\|^2+\lambda\|B-B_0\|_F^2.
\]

Формы: `X=(n,d)`, `B=(m,d)`, `U=(J,P,d)`, `I=(J,P)`, `L=(J,m)`.
LSMR, допуски, trust/proximal acceptance, случайные направления и внешний
выбор шага `best` сохранены. Численная эквивалентность отдельного вычисления
не означает побитового совпадения всей адаптивной траектории.

**EXACT — поиск массы.** Для стандартного ядра
`K(t)=max(1-t²,0)`, где `t` — квадрат анизотропного расстояния / `h²`,
используется монотонное исключение нулевых весов. При принятом `alpha=low`
пара с `(low²*r+p)/h²>=1` нулевая для всех оставшихся `alpha>=low`.
Здесь `p=sum(lambda_q*(Delta @ basis_q)²)`,
`r=max(||Delta||²-sum((Delta @ basis_q)²),0)` для `orthogonal`,
`r=||Delta||²` для `full`. Критерий — полная масса `J*N_loc`, не `n_eff`.
Бисекция сохраняет допуск `sqrt(eps)`; для bandwidth сохранены 60 шагов.
При уменьшении bandwidth аналогично исключаются уже нулевые пары.
Для произвольного пользовательского ядра остаётся общий поиск.

Из `main` взята идея работы только по возможному support. Сортировка всех
breakpoint и suffix-полиномы не перенесены: здесь оставлена прямая сумма
ядра, без вычитания большого числа почти единичных слагаемых из числа пар.
Память поиска `alpha` — `O(E_0+B*n)`, где `E_0` — support при `alpha=0`,
`B=config.batch_size`; это может быть почти `J*n` на плотной задаче.
Bandwidth держит дополнительную копию кандидатов только после сокращения
как минимум вдвое. Полная матрица исходных расстояний пока сохраняется.

**EXACT — повторное использование и streaming.** Проекции `X @ basis`
вычисляются один раз при построении весов, вместо повтора для каждого блока.
Инициализация вычисляет веса одной строки непосредственно перед её LS-fit:
удалена полная матрица `W=(J,n)`. На `J=500,n=10000` это 40 MB float64.

**NUMERICAL — общий сдвиг координат.** До Gram identity и проекций вычитается
общий origin. Проверено против прямых разностей при offset `1e12`.
Это устраняет конкретный источник cancellation, но не обещает точность для
произвольного динамического диапазона входных данных.

**NUMERICAL — локальная ridge-SVD при `k<d`.** Свободный intercept исключается
weighted centering, затем для `A=diag(sqrt(w))*(X-local_mean)=U diag(s) V.T`
градиент вычисляется как `V diag(s/(s²+ridge)) U.T y_centered`.
Деление реализовано через `hypot(s,sqrt(ridge))`. Нет normal matrix или
добавленных `d` ridge-строк. Консервативная граница сингулярных чисел проверяет,
что исходный augmented `rcond=eps*max(n+d,d+1)` ничего не отсёк бы.
При нулевом ridge либо небезопасной границе выполняется исходный augmented LS.
При `k>=d` он также сохранён: отдельный бенчмарк показал регрессию времени
и памяти у полного SVD. Нельзя распространять выигрыш случая `k<d` на все
локальные задачи.

## Отдельный оцениватель: `local-cv`

Новая опция `--index-init local-cv` меняет только выбор ridge при локальной
инициализации (**ESTIMATOR**); обычный `local` остаётся default.
Python API: `initialize_basis_local_with_spectrum(..., ridge_selection="loo")`;
тот же keyword доступен у `initialize_basis_local` и `initialize_beta_local`.

При фиксированных локальных весах выбирается minimum weighted PRESS:

\[
\operatorname{PRESS}(\lambda)
=\sum_i\left(\frac{e_i}{1-H_{ii}}\right)^2,\qquad
H=\frac{vv^T}{v^Tv}+U\operatorname{diag}
\left(\frac{s^2}{s^2+\lambda}\right)U^T,\quad v=\sqrt w.
\]

`e` — residual в weighted координатах. Локальные веса и bandwidth при
удалении наблюдения фиксированы. Это точная leave-one-out формула для
данной weighted линейной модели, не независимая проверка всего ADP.
Сетка: `max(local_ridge, s_max² * 10**q)`, `q=-6,...,2`, плюс
`local_ridge` как отдельный кандидат. При `1-H_ii<=sqrt(eps)` кандидат
отклоняется; отсутствие допустимого кандидата приводит к явному отказу.
Сетка — инженерный выбор, а не теорема об оптимальном восстановлении EDR.
Её достаточно записать вместе с `local_ridge`, данными и seed для повторения.

В CLI/experiment validation новый вариант проходит те же ограничения `N_lin`
и training-size, что `local`. В подборе не используются истинный базис или
метрика восстановления. Проверка PRESS сравнивает выбранный ridge с явным
переобучением после удаления каждого наблюдения при неравных весах.

## Измерения

Intel Core i5-12400F, Python 3.13.12, NumPy 2.5.2, SciPy 1.18.1, float64,
один поток OpenBLAS/OMP/MKL. Версии BLAS, исходники SHA256 и dirty state
сохранены в JSON. Микробенчмарки имеют прогрев, медиану повторов и отдельный
проход `tracemalloc` для памяти. Он не учитывает все native allocations.
Полные fits идут в отдельных процессах; RSS — process high-water, времена
штатного runner включают его tracing. Порядок A/B чередуется по seed.

Полные fits, медианы трёх seed:

| n,d,m | До, s | После, s | До/после | RSS до, MiB | RSS после, MiB |
|---|---:|---:|---:|---:|---:|
| 3000,100,2 | 4.317 | 4.451 | 0.97 | 114.0 | 113.9 |
| 10000,100,10 | 16.048 | 10.449 | 1.54 | 357.5 | 218.5 |

На малой точке выигрыш полного fit не подтверждён: разброс времени
3.82–8.83 s. Этот стенд не изолирован от внешней нагрузки.
Сравнение отдельных ядер ниже измерено отдельно от tracing.

Максимальная Frobenius-разница проекторов до/после:
`2.64e-08` для m=2 и `0.0057` для m=10;
разница ошибки относительно истины — соответственно `1.3e-09`
и `4.73e-05`. Многошаговый m=10 чувствителен к округлению;
для всего обучения не заявляется эквивалентность базисов с допуском 1e-10.

Микробенчмарк поиска, `n=10000,d=100,J=500,m=2`, пять повторов:

| Этап | Dense, s | Compact, s | Dense traced peak, MB | Compact traced peak, MB |
|---|---:|---:|---:|---:|
| bandwidth | 1.1368 | 0.1400 | 80.0 | 80.0 |
| alpha | 0.9320 | 0.2139 | 200.2 | 62.8 |

Возвращённые h и alpha совпали в этом микробенчмарке.
При `(k=300,d=1000)` локальная ridge-SVD: 0.184 → 0.0293 s,
traced peak 32.4 → 14.0 MB, относительная ошибка градиента `3.12e-11`.
При `(k=2000,d=1000)` она проиграла: 0.302 → 0.533 s и 73.3 → 112.2 MB;
поэтому этот путь не включён для обычной переопределённой инициализации.

Качество `local` против `local-cv`, медианы трёх seed, m=2:

| n,d,noise | trace_score local | trace_score CV | projector_distance local | projector_distance CV | Выигравших seed |
|---|---:|---:|---:|---:|---:|
| 1000,30,0.05 | 0.9456 | 0.9477 | 0.1088 | 0.1046 | 1/3 |
| 1000,30,1.0 | 0.6619 | 0.7436 | 0.6762 | 0.5128 | 3/3 |
| 3000,100,0.5 | 0.5422 | 0.5897 | 0.9157 | 0.8206 | 3/3 |

Всего выигрыш в 7/9 пар; при малом шуме два seed слегка ухудшились.
Уменьшение медианной ошибки в двух шумных сериях — около 24% и 10%.
Все 30 окончательных fits завершились без численного отказа. Конечные
диагностики и причины остановки каждого fit сохранены в JSON; результат
по качеству не переименован в сертификат сходимости.

Время local/CV для n=1000, d=30, noise=0.05: 0.811/0.903 s.
Время local/CV для n=1000, d=30, noise=1.0: 0.658/0.688 s.
Время local/CV для n=3000, d=100, noise=0.5: 3.843/4.021 s.

Основная метрика **текущей ветки** — `trace_score=||B @ B_true||_F²/m`,
больше лучше. В новых benchmark JSON дополнительно вычисляется напрямую
`projector_distance=||B-(B @ B_true) @ B_true.T||_F²`, меньше лучше.
Она равна `m*(1-trace_score)` для ортонормальных базисов. Протокол CLI
не подменялся метрикой из старых заметок/другой ветки.

Качество проверено на `X~N(0,I)`,
`Y=sum(sin(z_q)+0.25*z_q²)+noise`, случайном ортонормальном истинном базисе.
Потоки данных, базиса, шума и метода разделены; A/B используют одинаковые
данные и одинаковые потоки метода. Направления изотропные, обновляются на
каждом внешнем шаге. Центры — без возвращения, `training_set=all`.
`N_loc=20`, `P=20`, `J=max(100,n/20)`, `N_lin=max(40,1.5*d)`;
до 6 внешних и 3 внутренних шагов, LSMR, прочие defaults сохранены в JSON.

Это ограниченная проверка, не универсальное преимущество `local-cv`.
Нельзя объявлять восстановление только по улучшению score: в частности,
качество `m=10` остаётся низким, а завершение по бюджету шагов не доказывает
сходимости AO. В таблицах не исключались неудачные численные результаты.
Предварительный финальный запуск прерван ошибкой файловой системы ENOSPC;
она записана отдельно в `validated_speed/storage_failure.json`, затем серия
полностью повторена в `/tmp`. Прежние артефакты не переписывались.

После оптимизации малой задачи `(1000,100,100,20,10)` профиль по-прежнему
показывает основное время в глобальном LSMR. Допуски не ослаблялись ради
скорости. Полное обучение `n=10000,d=1000` не измерено: отдельно проверены
локальные ridge-задачи размерности 1000. Одна `X` в таком stress-режиме
занимает 80 MB; `distance2` при `J=500` — 40 MB, каждый массив `U`/направлений
при `P=20` — ещё 80 MB. Эти persistent allocations остаются ограничением.

для графиков — `MPLCONFIGDIR=/tmp/adp-mpl`. Группа `bench` уже существовала;
новых зависимостей нет. Результаты окончательного повторения:

неравные веса, воспроизводимость полного CLI и существующие проверки
