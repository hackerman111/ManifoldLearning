Все 20 seed имеют строку результата, 9 сохранённых наборов `J=125` состоят
из 125 различных ID исходного случайного пула. Сумма измеренного wall по
строкам 8.758 с; process peak RSS 97.33 МиБ при одном потоке BLAS. Прямой
small dense test подтвердил weighted cross-covariance, порядок greedy и
logdet ratio; повторный запуск d10/d100 seed4000 воспроизвёл отсутствие
кандидата и точные 125 ID соответственно. Целевые Ruff/Pyright и pytest прошли.

Причина отсутствия кандидата — порог `coverage >=0.99`, а не logdet surrogate:
отношение `L_125/L_ref` больше единицы у всех seed, но это внутренняя
обучающая метрика, не EDR quality. Независимый пересчёт для d10 seed4000:
объединение support **всех** 500 исходных центров покрывает 0.987 обучающих
строк, допустимых — 0.959; greedy достигает ровно 0.959. Для d100 seed4008
все 500 покрывают 0.998, допустимые — 0.989; greedy достигает 0.989.
Таким образом, для этих seed заданный абсолютный порог невозможен даже при
полном допустимом пуле. Менять его после просмотра результатов нельзя без
нового независимого протокола.

Предзарегистрированная C2 граница требует `J<J₀` на каждом из 20 selection
seed; она провалена. C3 paired full fits, C4 held-out seed5000–5019 и
проверка H2 **не проводились**. Цель «меньше центров без ухудшения recovery»
не подтверждена и не опровергнута для других правил; этот конкретный
estimator-кандидат отклонён. Публичный multi-index default не изменён.
