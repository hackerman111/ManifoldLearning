# R3: H1 не прошёл замороженный full-fit gate

Дата: 2026-09-26. Источники: `r2_protocol.md`,
`selection/manifest.json`, `selection/runs.jsonl`,
`selection/summary.json`. Selection выполнен один раз на seed
61000–61005. В manifest и после прогона fingerprint равен
`97f76bb8d9b7a5dc383638882ddee7a1ced86ac8fa8f11ea88d09e8ea75c408a`;
скрипт — `f43e658305f8b8f9ee881abff424625080d5ab23c23388d2abf7c2829ab63666`.
Все 66 запланированных записи существуют и уникальны по `(case,variant,seed)`;
внутри каждой seed-группы одинаковый `model_seed`. Девять ошибок — только
`RuntimeError` на m=2, по три для каждого варианта.

Показаны отношения медианы **парных** H1/baseline измерений; значения
`<1` выгодны. `Δquality` положителен при улучшении: multi — разность
`trace_score`, manifold — снижение RMS principal sine. Нулевых recovery
во всех вариантах/точках; multi HPAO не сошёлся ни в одном fit. Manifold
m=1 completion 6/6 для обоих; m=2 completion 3/6, три пары оборвались
из-за локального rank. `pairs` в машинном summary означает шесть
наличеств пар строк, включая errors; **полных** пар m=2 только три.

| Точка | Полные iid/H1 пары | Seed с потерей качества `>1e-10` | Худший `Δquality` | Median wall H1/iid | Median RSS H1/iid | Gate |
|---|---:|---|---:|---:|---:|---|
| multi d10 | 6/6 | 61002, 61004 | −0.002114 | 0.820 | 0.836 | fail: качество и speed `<=0.8` |
| multi d100 | 6/6 | 61004 | −0.001136 | 1.028 | 0.907 | fail: качество, нет ускорения |
| manifold m1 | 6/6 | 61000, 61001 | −0.008486 | 1.009 | 0.998 | fail: качество, нет ускорения |
| manifold m2 | 3/6 | 61002, 61005 | −0.018003 | 1.000* | 0.995* | fail: rank/error и качество |

`*` M2 стоимость рассчитана только по трём завершённым парам и не проходит
требование шести. Ошибки baseline/H1 на seed 61000, 61001, 61003
совпадают по наличию, но это не успешные fit и не recovery. На seed 61002
и 61005 H1 хуже baseline. Ни один кандидат не показал прироста recovery,
который мог бы открыть второй путь gate.

Контроль `iid_budget` с тем же числом фактических строк запускался для
d10/m1/m2. Для d10 у H1 только **1/6** пар качество выше, чем у
`iid_budget`, а median wall H1/контроль `0.992`. Медиана контроля к
номинальному baseline по wall `0.813`, RSS `0.839`, H1 — `0.820/0.836`.
Это согласуется с тем, что наблюдаемая экономия d10 в основном связана с
10 вместо 40 строк, а не с доказанной выгодой ортогональности; причинный
вывод по шести seed не делаем. Сам `iid_budget` ухудшил качество против
номинального baseline на seed 61003, поэтому он тоже не проходит
строгий per-fit критерий. Для m1 H1 лучше same-row контроля по качеству
только в 3/6 пар; m2 даёт лишь 3 завершённые пары.

Для d10 bootstrap 95% интервал медианы H1/iid wall из frozen summary
`[0.788, 0.830]`, RSS `[0.833, 0.983]`; d100 wall `[1.018, 1.042]`,
m1 wall `[0.986, 1.026]`. Это описательные интервалы для данного
selection и среды, не независимая validation.

**Решение:** R3 stop condition сработало для всех четырёх точек.
Не менять threshold, seed или estimator после просмотра результатов.
R4 на held-out 62000–62019 не запускался; production ADP/default/API не
менялись. Теорема H1 остаётся теоремой о фиксированной квадратичной цели,
без доказанного улучшения полного ADP fit. H2 и H3 требуют отдельного
нового proof/protocol цикла, а не продолжения этой selection.
