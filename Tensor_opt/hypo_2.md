## 1. Самый сильный вывод: оптимизировать надо support, а не форму веса

Пусть для центра (x_j)

[
\mathcal N_j={i:w_{ij}>0},
\qquad
k_j=|\mathcal N_j|,
]

а

[
C_j=
\sum_{i\in\mathcal N_j}
w_{ij}(X_i-\bar X_j)(X_i-\bar X_j)^\top,
\qquad
U_j=\Phi_j C_j.
]

В предыдущем выводе уже получена факторизация

[
C_j=R_j^\top R_j,
\qquad
U_j=Q_jR_j,
]

и граница

[
\operatorname{rank} C_j\le k_j-1.
]

Её можно усилить.

**Теорема.** Если все (w_{ij}>0) на фиксированном (\mathcal N_j), то

[
\boxed{
\operatorname{rank} C_j
=======================

\operatorname{affdim}{X_i:i\in\mathcal N_j}.
}
]

Действительно,

[
v^\top C_jv
===========

\sum_{i\in\mathcal N_j}
w_{ij}
\left[v^\top(X_i-\bar X_j)\right]^2.
]

При положительных весах это равно нулю тогда и только тогда, когда

[
v^\top(X_i-\bar X_j)=0
\qquad
\forall i\in\mathcal N_j.
]

Следовательно,

[
\operatorname{range} C_j
========================

\operatorname{span}
{X_i-\bar X_j:i\in\mathcal N_j}.
]

Поскольку (\bar X_j) лежит в аффинной оболочке соседей,

[
\dim \operatorname{span}
{X_i-\bar X_j}
==============

\operatorname{affdim}{X_i}.
]

Отсюда

[
\boxed{
\operatorname{rank}U_j
\le
\min\left{
p,,
\operatorname{affdim}\mathcal N_j
\right}
\le
\min{p,k_j-1}.
}
]

Это даёт довольно жёсткий отрицательный результат:

[
\boxed{
\text{изменение значений положительных весов при неизменном support
не уменьшает точный локальный ранг.}
}
]

То есть переход Epanechnikov (\to) biweight (\to) triweight (\to) Wendland с тем же support **не сделает (U_j) ниже рангом**. Уменьшить ранг через ядро можно только изменением множества ненулевых весов.

Компактные кусочно-полиномиальные ядра вроде функций Wendland действительно существуют, но их вычислительное преимущество здесь ограничивается компактным support; при одинаковом support они не меняют полученную выше ранговую структуру. ([Springer Link][1])

# 2. Из критерия нулевого веса получается exact-фильтр центров

Для single-index у нас уже есть усиленный screening

[
q_{ij}
======

\frac{
\alpha^2D_{ij}+s_{ij}^2
}{h^2},
\qquad
s_{ij}=\beta^\top(X_i-x_j),
]

и

[
\boxed{
|s_{ij}|
\ge
\frac{h}{\sqrt{1+\alpha^2}}
\Longrightarrow
w_{ij}=0.
}
]

Причём это максимальный exact-критерий, использующий только (s_{ij}).

Определим дешёвую кандидатную окрестность

[
\mathcal C_j
============

\left{
i:
|\beta^\top X_i-\beta^\top x_j|
<
\frac{h}{\sqrt{1+\alpha^2}}
\right},
]

и

[
c_j=|\mathcal C_j|.
]

Тогда всегда

[
\boxed{\mathcal N_j\subseteq\mathcal C_j}
]

и поэтому

[
\boxed{k_j\le c_j.}
]

Здесь появляется именно тот механизм выбора центров, о котором ты говоришь.

После одного вычисления

[
z_i=\beta^\top X_i
]

и сортировки (z_i) величина (c_j) получается двумя binary search. Для всех центров:

[
O(nd+n\log n+J\log n),
]

без вычисления (d)-мерных расстояний для каждого центра. Похожий projected search уже получен для weights stage.

Теперь (c_j) можно использовать **до построения статистик**.

Если

[
c_j\le K,
]

то автоматически

[
k_j\le K
]

и

[
\boxed{
\operatorname{rank}U_j\le\min(p,K-1).
}
]

Это уже exact-гарантия низкого ранга, полученная без вычисления самого (U_j).

Есть и противоположный exact-тест. Для effective sample size

[
n_{\rm eff,j}
=============

\frac{(\sum_iw_{ij})^2}{\sum_iw_{ij}^2}
]

по Коши

[
n_{\rm eff,j}\le k_j\le c_j.
]

Поэтому

[
\boxed{
c_j<n_{\rm eff,min}
\Longrightarrow
n_{\rm eff,j}<n_{\rm eff,min}.
}
]

Такой центр можно выбросить, даже не вычисляя его веса.

Для текущего ядра (0\le K(q)\le1) есть ещё

[
M_j=\sum_iw_{ij}\le k_j\le c_j,
]

поэтому

[
\boxed{
c_j<n_{\min}
\Longrightarrow
M_j<n_{\min}.
}
]

То есть дешёвый zero-screening одновременно даёт:

[
\text{reject плохих центров} +
\text{upper bound на стоимость} +
\text{upper bound на ранг }U_j.
]

# 3. Rank-aware выбор центров вместо случайного

В старом анализе уже рассматривались random centers, стратификация по пилотному индексу и k-means++, но специальной гарантии именно для ADP там не было.

Теперь можно определить **допустимый пул**

[
\mathcal A_K
============

\left{
j:
n_{\rm eff,min}\le c_j\le K
\right}.
]

Верхняя граница имеет строгий смысл:

[
j\in\mathcal A_K
\quad\Longrightarrow\quad
\operatorname{rank}U_j\le K-1.
]

Нижняя граница пока не гарантирует хорошую локальную массу, потому что (c_j) представляет только верхнюю границу (k_j). Но после предварительного отбора для такого центра требуется проверить не более (K) кандидатных точек. Поэтому точная верификация всех центров из (\mathcal A_K) стоит

[
O(|\mathcal A_K|Kd)
]

вместо

[
O(Jnd).
]

После неё получаем настоящий sparse hypergraph

[
j\longleftrightarrow \mathcal N_j.
]

Теперь случайный выбор центров можно заменить задачей покрытия.

Для множества центров (S) определим

[
F_L(S)
======

\sum_{i=1}^n
a_i
\min
\left{
L,,
\sum_{j\in S}\mathbf 1{i\in\mathcal N_j}
\right},
\qquad a_i\ge0.
]

При (L=1) это доля наблюдений, покрытых хотя бы одной выбранной окрестностью. При (L=2) мы поощряем покрытие каждой точки двумя центрами.

Эта функция монотонна и субмодулярна. Добавление центра (j) приносит вклад только наблюдениям, которые ещё покрыты менее (L) раз. При увеличении уже выбранного множества число таких наблюдений не увеличивается.

Поэтому обычный greedy

[
j_*=
\arg\max_{j\notin S}
\left[F_L(S\cup{j})-F_L(S)\right]
]

при ограничении (|S|\le J_*) удовлетворяет классической оценке

[
\boxed{
F_L(S_{\rm greedy})
\ge
(1-1/e)
\max_{|S|\le J_*}F_L(S)
}
]

для рассматриваемого допустимого пула. Это стандартный результат Nemhauser, Wolsey и Fisher. ([Springer Link][2])

Получается уже не просто эвристика:

[
\boxed{
\text{hard rank cap} +
\text{гарантированное приближение к оптимальному coverage}.
}
]

Гарантия относится именно к coverage-критерию среди центров в (\mathcal A_K), а не к ошибке восстановления (\beta).

# 4. Почему это лучше случайных центров вычислительно

Пусть выбрано (J_*) центров и

[
k_j\le K.
]

Тогда число рёбер weight graph удовлетворяет

[
\boxed{
E=\sum_{j\in S}k_j\le J_*K.
}
]

Следовательно, все последующие sparse statistics получают детерминированный верхний предел.

Для factorized ADP из предыдущего результата память локального представления имеет порядок

[
O(Ep+E),
]

вместо

[
O(J_*pd)
]

для явных (U_j).

Подставляя (E\le J_*K):

[
\boxed{
M_{\rm local}
=============

O(J_*pK+J_*K).
}
]

Размерность (d) исчезает из хранения локальных статистик.

Например, при

[
d=1000,\qquad
p=10,\qquad
J_*=500,\qquad
K=20,
]

явный (U) содержит

[
500\cdot10\cdot1000=5,000,000
]

`float32`, то есть около (20) MB.

Фактор (Q) содержит

[
500\cdot10\cdot20=100,000
]

чисел, около (0.4) MB.

Это тот же механизм, который для (J=2000), (K=20) уже давал сокращение (U)-части примерно в (50) раз.

# 5. Ещё сильнее: выбирать центры по стабильности zero pattern

Из предыдущего анализа между двумя outer steps имеем

[
A_k=T_k^2,
\qquad
q_{ij}^{(k)}=\Delta_{ij}^\top A_k\Delta_{ij},
]

и

[
\eta_k=|A_k-A_{k-1}|_2.
]

Тогда

[
\left|
q_{ij}^{(k)}-q_{ij}^{(k-1)}
\right|
\le
\eta_kD_{ij}.
]

Отсюда уже были получены сертификаты

[
q_{ij}^{(k-1)}-\eta_kD_{ij}\ge1
\Longrightarrow
w_{ij}^{(k)}=0,
]

и

[
q_{ij}^{(k-1)}+\eta_kD_{ij}<1
\Longrightarrow
w_{ij}^{(k)}>0.
]

Определим для центра число **неопределённых рёбер**

[
u_j^{(k)}
=========

#

\left{
i:
\left|
q_{ij}^{(k-1)}-1
\right|
\le
\eta_kD_{ij}
\right}.
]

Только эти пары потенциально способны изменить zero/nonzero status.

Это даёт новый параметр выбора центра:

[
\boxed{
u_j^{(k)}
=========

\text{верхняя оценка числа support changes на следующем шаге}.
}
]

При одинаковом coverage я бы предпочитал центр с меньшим (u_j).

Можно даже ограничить пул

[
\mathcal A_{K,U}
================

{j:c_j\le K,\ u_j\le U}
]

и уже внутри него выполнять greedy coverage. Тогда сохраняется (1-1/e)-гарантия для coverage относительно лучшего множества в этом пуле, одновременно получаем ограничения

[
E\le J_*K
]

и

[
\text{число потенциально меняющихся рёбер}
\le J_*U.
]

Это уже **support-stable center selection**.

# 6. Здесь появляется ядро, которое действительно имеет вычислительный смысл

У текущего Epanechnikov

[
K_E(q)=(1-q^2)_+.
]

Даже если между шагами support не изменился, при

[
q_{ij}^{(k)}\ne q_{ij}^{(k-1)}
]

ненулевой вес обычно изменяется:

[
K_E(q_{ij}^{(k)})
\ne
K_E(q_{ij}^{(k-1)}).
]

Поэтому неизменившийся zero pattern не позволяет полностью переиспользовать локальные статистики.

Рассмотрим вместо этого box kernel

[
\boxed{
K_{\rm box}(q)=\mathbf1{q<1}.
}
]

При том же (T,h) его support совпадает с support текущего Epanechnikov:

[
w_{ij}>0
\iff
q_{ij}<1.
]

Но теперь вес целиком определяется одним битом support.

Если между двумя outer steps для центра (j)

[
\mathcal N_j^{(k)}
==================

\mathcal N_j^{(k-1)},
]

то

[
W_j^{(k)}=W_j^{(k-1)}
]

**точно**.

Следовательно, без пересчёта (X) можно переиспользовать:

[
\bar X_j,\qquad
C_j,\qquad
b_j,\qquad
R_j.
]

При factorized ADP новые случайные направления требуют только нового

[
Q_j=\Phi_jR_j^\top,
]

а не повторного построения локальной covariance по данным.

Это принципиальное отличие от Epanechnikov.

---

# 7. У box kernel есть ещё два строгих вычислительных свойства

При (k_j) соседях

[
w_{ij}=1.
]

Поэтому

[
m_j=k_j
]

и

[
n_{\rm eff,j}
=============

# \frac{k_j^2}{k_j}

k_j.
]

Более того, среди **любых** положительных весов на фиксированном support

[
n_{\rm eff}
===========

\frac{(\sum_iw_i)^2}{\sum_iw_i^2}
\le k
]

по Коши, причём равенство достигается только при одинаковых весах.

То есть

[
\boxed{
K_{\rm box}
\text{ максимизирует }n_{\rm eff}
\text{ при фиксированном support}.
}
]

Это не доказывает меньшую статистическую ошибку ADP, потому что taper у границы влияет на bias. Но именно по критерию effective sample size box kernel оптимален.

Второй выигрыш касается памяти. В neighbor-list representation для box kernel значения весов вообще хранить не требуется. При `int32` indices и `float32` weights обычное ребро содержит примерно

[
4+4=8\text{ байт}
]

полезной информации, а binary edge требует только

[
4\text{ байта}
]

индекса.

# 8. Компромисс: квантованное компактное ядро

Box kernel может оказаться слишком грубым. Между ним и Epanechnikov есть интересная вычислительная конструкция:

[
K_Q(q)
======

\begin{cases}
c_1,&0\le q<\tau_1,\
c_2,&\tau_1\le q<\tau_2,\
\vdots\
c_L,&\tau_{L-1}\le q<1,\
0,&q\ge1.
\end{cases}
]

Например (L=2):

[
K_Q(q)
======

\begin{cases}
1,&q<\tau,\
\gamma,&\tau\le q<1,\
0,&q\ge1.
\end{cases}
]

Его преимущества вычислительно строгие относительно **этого нового kernel**.

Вес хранится как маленький integer label вместо `float`; изменение (q) не требует пересчёта статистики, пока пара не пересекла одну из границ

[
\tau_1,\ldots,\tau_{L-1},1.
]

Если

[
|q^{(k)}-q^{(k-1)}|\le\delta_{ij},
]

то вес гарантированно сохраняется, если интервал

[
[q^{(k-1)}-\delta_{ij},
q^{(k-1)}+\delta_{ij}]
]

не содержит ни одного breakpoint (\tau_\ell).

С

[
\delta_{ij}=\eta_kD_{ij}
]

получаем exact event-driven update.

Box kernel представляет случай (L=1).

Это, на мой взгляд, более интересное направление, чем Wendland: **Wendland даёт гладкий compact support, а quantized kernel позволяет реально не обновлять большую часть весов между outer steps**. Wendland был построен именно как класс компактно поддержанных кусочно-полиномиальных радиальных функций, но его гладкость сама по себе не уменьшает число ненулевых рёбер ADP. ([Springer Link][1])

# 9. Самая агрессивная версия: fixed-(K) adaptive support

Если мы готовы изменить сам estimator сильнее, можно гарантировать разреженность не выбором удачных центров, а конструкцией bandwidth.

Для центра (j) пусть

[
r_{ij}
======

\Delta_{ij}^\top A_k\Delta_{ij}
]

представляет ненормированное адаптивное расстояние.

Пусть

[
r_{j,(1)}
\le\cdots\le
r_{j,(n)}
]

его order statistics.

Если нет ties, выбираем

[
r_{j,(K)}
<
h_j^2
<
r_{j,(K+1)}.
]

Тогда для любого kernel, положительного при (q<1) и нулевого при (q\ge1),

[
\boxed{k_j=K.}
]

Отсюда одновременно

[
\boxed{
E=JK,
}
]

[
\boxed{
\operatorname{rank}C_j\le K-1,
}
]

[
\boxed{
\operatorname{rank}U_j
\le\min(p,K-1).
}
]

Если взять box kernel, дополнительно

[
\boxed{
n_{\rm eff,j}=K
}
]

для каждого центра.

Это уже очень сильная вычислительная конструкция:

[
\boxed{
\text{fixed-}K +
\text{compact support} +
\text{factorized }U
}
]

даёт детерминированную память

[
O(JK+JpK)
]

и исключает ситуацию, когда случайно возникшая очень плотная локальная окрестность съедает память.

Variable-bandwidth и nearest-neighbor bandwidth давно исследуются в kernel и local-polynomial методах. Fan и Gijbels рассматривали data-driven variable bandwidth и spatial adaptation, а Mack и Rosenblatt анализировали (k)-NN bandwidth в непараметрическом оценивании. Но их результаты **не доказывают корректность именно fixed-(K) ADP**, поэтому для ADP это новая модификация, которую нужно проверять отдельно. ([OUP Academic][3])

Для твоих размеров здесь особенно пригоден уже найденный cache

[
D_{ij}=|X_i-x_j|^2.
]

При (n=J=2000) он занимает (16) MB в `float32`, после чего single-index adaptive distances на каждом шаге считаются за

[
O(nd+Jn)
]

вместо (O(Jnd)).

Тогда fixed-(K) support можно получать через `nth_element` по строкам без повторного чтения (d=1000) координат.

# 10. Что с другими стандартными ядрами

| Kernel              | Exact zeros | Меньше rank при том же support |  Weight storage |   Exact reuse при неизменном support |
| ------------------- | ----------: | -----------------------------: | --------------: | -----------------------------------: |
| Epanechnikov        |          да |                            нет |           float |                                  нет |
| triangular/tent     |          да |                            нет |           float |                                  нет |
| biweight/triweight  |          да |                            нет |           float |                                  нет |
| Wendland            |          да |                            нет |           float |                                  нет |
| box                 |          да |                            нет |    **не нужен** |                               **да** |
| (L)-level quantized |          да |                            нет | маленький label | **да, пока не пересечён breakpoint** |
| Gaussian            |         нет |                            нет |           dense |                                  нет |

Поэтому я бы не искал kernel, который каким-то специальным polynomial profile сделает (U) малоранговой.

Строгий вывод:

[
\boxed{
\text{low rank }U
\Longleftarrow
\text{малый/низкоразмерный support},
}
]

а не специальная форма (K(q)>0) внутри support.

И аналогично kernel сам по себе в общем случае **не сделает (U_j) разреженной по координатам**. Каждая строка (U_j) представляет сумму плотных векторов (X_i-\bar X_j). При плотных (X_i) никаких структурных нулей в координатах из scalar weights не следует. Разреживать надо (W), а (U) хранить факторизованно.

# 11. Какой алгоритм я бы поставил первым

Я бы начал с версии, которая не меняет ядро и global bandwidth:

1. На каждом outer step вычислить дешёвые screening sets (\mathcal C_j) для всех потенциальных центров.
2. Выкинуть центры с (c_j<n_{\rm eff,min}).
3. Ограничить пул центрами (c_j\le K_{\max}). Это сразу даёт exact rank cap.
4. Только для этого пула вычислить настоящие (\mathcal N_j) и (n_{\rm eff,j}); на центр требуется не более (K_{\max}) полных проверок.
5. Выбрать (J_*) центров greedy-максимизацией (F_L(S)), а не случайно.
6. Считать статистики только на выбранном sparse graph и использовать (U_j=Q_jR_j).

Это меняет способ выбора центров, но **не меняет формулу веса, kernel или локальные статистики выбранных центров**.

После этого я бы отдельно тестировал более агрессивную конструкцию

[
\boxed{
\text{support-aware centers} +
\text{fixed-}K\text{ local bandwidth} +
\text{box или 2-level kernel} +
\text{event-driven updates}.
}
]

Она уже меняет estimator, зато даёт три жёстких вычислительных свойства одновременно:

[
E=JK,
]

[
\operatorname{rank}U_j\le K-1,
]

и при box kernel пересчёт локальной статистики нужен только у центров, support которых действительно изменился.

Единственная существенная оговорка для динамического выбора центров: он меняет распределение центров и может переоценивать области с небольшими окрестностями. В старом анализе уже отмечено, что coverage-based centers требуют корректировки весов центров, иначе меняется целевой average functional. Поэтому для первой реализации я бы либо фиксировал выбранный после первого структурного шага набор центров, либо добавлял явные веса, компенсирующие число исходных центров, которые представляет каждый выбранный центр.

Из всего рассмотренного здесь наиболее сильной новой конструкцией мне кажется именно **screening-aware rank-constrained center selection**: критерий нулевости веса используется до построения статистик, чтобы заранее обеспечить (k_j\le K), затем greedy coverage убирает почти дублирующие локальные окрестности. В отличие от простого «выбирать центры с малым числом соседей», у этой схемы есть точная ранговая гарантия и (1-1/e)-гарантия для сформулированного критерия покрытия.
