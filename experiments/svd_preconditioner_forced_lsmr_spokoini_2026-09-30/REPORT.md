# Предобуславливатель при принудительном LSMR на задаче Spokoiny

## Результат

На той же тяжёлой задаче (`n=800`, `d=50`, `m=2`) принудительное
предобуславливание сократило медианное парное время полного fit на **5,44%**:
с 41,83 до 38,76 с. Все три пары показали ускорение. Медианное число
LSMR-итераций снизилось на **12,95%** по парным отношениям. Во всех запусках
диагностика подтвердила `direct_solves=0`, положительное число LSMR-итераций
и отсутствие fallback; при включённой опции кэш диагонали составил 320 000 B.

| Seed | LSMR без / с | Изменение итераций | Время без / с, с | Изменение времени | Ошибка проектора без / с |
|---:|---:|---:|---:|---:|---:|
| 0 | 35 556 / 31 331 | −11,88% | 40,263 / 38,758 | −3,74% | 0,1183134 / 0,1183134 |
| 1 | 44 227 / 38 498 | −12,95% | 43,603 / 41,231 | −5,44% | 0,0898671 / 0,0898671 |
| 2 | 40 380 / 32 498 | −19,52% | 41,830 / 38,692 | −7,50% | 0,1033300 / 0,1010096 |
| Медианное парное отношение | — | **−12,95%** | — | **−5,44%** | — |

Все варианты прошли 162 внешних шага и остановились по `h_min`; индикатор
`svd_inner_converged` остался `false` во всех шести fit, как и в прежнем
прямом прогоне. Для seed 0 и 1 ошибки проектора отличаются лишь примерно на
`1e-10`. На seed 2 разница составила `−0,00232` в пользу предобусловленного
варианта. Значит, небольшое изменение итеративного решения проявилось в одном
из трёх внешних fit; качество в паре нельзя считать тождественным.

Каждый fit превысил исходный бюджет 30 с. Поэтому предобуславливатель
ускоряет именно принудительный LSMR путь, но этого недостаточно, чтобы
уложиться в исходный бюджет. Он также не делает LSMR конкурентным прямому
решению на этой задаче: прямые paired-прогоны занимали около 25,7 с. Медианный
process peak RSS был 99,66 MiB без опции и 99,48 MiB с ней; измерение включает
импорт и данные, поэтому не позволяет приписать небольшую разницу солверу.

## Метод

Повторён полный Spokoiny fit из
`experiments/svd_preconditioner_spokoini_2026-09-30/REPORT.md`: одинаковые
данные и init для каждой пары seed 0, 1, 2; `float64`; один поток BLAS;
свежий subprocess на fit; чередование порядка запуска. В каждом вызове
`solve` передан `direct_max_dimension=None`, а менялся только
`precondition_v`. Сохранены исходные tolerances, начальные условия и внешний
график. Таймер охватывает fit; RSS — `ru_maxrss`; `tracemalloc` не включён.

Полные строки и сводка: `runs.jsonl`, `summary.json`; настройки и хеши:
`manifest.json`. Перезапуск:

```sh
rtk proxy env OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 UV_CACHE_DIR=/tmp/adp-uv-cache PYTHONPATH=. uv run --no-sync python experiments/svd_preconditioner_forced_lsmr_spokoini_2026-09-30/benchmark.py
rtk proxy env UV_CACHE_DIR=/tmp/adp-uv-cache uv run --no-sync python experiments/svd_preconditioner_forced_lsmr_spokoini_2026-09-30/analyze.py
```

Вывод ограничен тремя парными seed и этой задачей. Метрики измеряют
фиксированные настройки LSMR; допуски не подбирались по этим результатам.
